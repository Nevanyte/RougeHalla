# Bounded player Fire proofs

These are actual TypeScript module probes for the explicit `HOLY_MODULES` installation, including `factions` and excluding Fire roam and other auxiliary installers. They do not establish full Fire installation or full game parity. No package source or dependencies are changed.

The four ordinary input/lifecycle traces are in `parity/legacy-capture/scenarios/fire.ts`; their 540 ticks compare performed requests, complete raw ledger, landed rows, private Burn/Disease buckets, clocks, engagement, pause, bits, ordinary events and outcomes. Missing/extra diagnostics and changed installation provenance fail comparison. Every tick restores and continues with the same next-step output/hash.

The standalone helpers are intentionally different from ordinary input traces:

- `ledger-matrix.ts` calls actual `recordHit`/`applyLedger` and the installed faction afterDamage function for twelve synthetic ledger setups. It tests instant hit caps versus proportional combined DoT budgets, barriers, immunity, overkill, departed sources, disabled PvP, scaling and distinct victims. Rust checks complete landed/player/bucket rows and emitted pre-barrier Backlash against actual source hook rows. These inputs isolate accounting and are not claims that each mixed entry is generated by one faction.
- `hidden-instant.ts` establishes contacts through actual attacks, then changes trusted positions/inventory/common barrier as documented in its setup. It never injects HP, ledger damage, signature targets or replacement functions. Three hidden bow Fire actors and four hidden fists Fire actors leave identical visible actor history. Tick13's real target whiff produces three/four raw Backlash rows with the exact same total. Rust reproduces the individual raw amounts and visible history, and projects one anonymous row with no weapon. Existing legacy memory is retained, and the source visibility reads are checked as read-only.

`source-manifest.json` pins source SHA-256 values, the source revision and proof outputs. Fixture `legacyRevision: unknown` reflects the capture container's missing git executable; all other captured values are actual oracle output. The manifest supplies source identity independently.

Run in the pinned Linux x64 Node22.23.4 container. Both standalone helpers reject other runtime identities. The image requires a writable `/repo/node_modules` temporary mount, an external writable `/out`, `npm ci --ignore-scripts --no-audit --no-fund`, then:

```
npx --yes --package node@22.23.4 node --import tsx tools/fire-fixtures/ledger-matrix.ts /out/ledger-matrix.json
npx --yes --package node@22.23.4 node --import tsx tools/fire-fixtures/hidden-instant.ts /out/hidden-instant.json
```

Compare the resulting files byte-for-byte with `parity/fire/`. Ordinary trace capture uses the existing `capture.ts --out /out --only <scenario>` interface.

Rust validation: `cargo test -p rh-parity --test fire`, `cargo test -p rh-sim --lib systems::fire`, `cargo test -p rh-sim --lib fx_projector`, `cargo test -p rh-headless --test fire`, `cargo test -p rh-policy --lib fire_instant`, `cargo test -p rh-server --lib live_fire_feed`, and `cargo test -p rh-sim --test no_alloc -- --nocapture`.

The public report has separate 128 retained DoT buckets and 16 report-local instant buckets, a single ledger-return marker before Holy, 20 operations and capacity for 784 output events. Unsupported performed-request totals/per-owner counts, instant rows and markers fail explicitly. Protocol5 omits all signature-qualified FX and signature bits; Unity support remains open. Warmed allocation checks cover all projector feeds and three 110-step Fire traces after 40 warmup ticks; result-bearing terminal steps remain excluded by the established allocation definition.
