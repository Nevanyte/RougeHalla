# CLAUDE.md — raid-br

Top-down 2.5D roguelike battle arena skeleton: last one standing wins Glorious Victory (GV, cosmetics-only). Phaser 4 client, Colyseus 0.18 authoritative server, npm workspaces monorepo. Colored shapes only.

## Commands
```
npm install            # once, at the root
npm run dev            # server :2567 + client :5173 (concurrently)
npm test               # vitest in every workspace (server includes the e2e bot run)
npm run typecheck      # tsc --noEmit in every workspace
npm run bots -- 3      # 3 headless bots join the running dev server
npm run bots -- -- 3 --url http://host:2567   # flags (--url, --prefix, --faction <id|rotate|random>, --loop to keep queuing, --verbose) need the second `--`: the root script nests npm, which eats them
npm run harness -w @raid/server               # weapon duel harness (report only, never fails; ~45 s): matrix, style grids (ranged stand/strafe/kite, melee stand/weave/jink), edge verdicts (HOLDS/FAILS, with thin faction columns), kiting; add `-- --core` to skip the sensitivity passes (~30 s), `-- --quick` for a few seconds, or `-- --grid-setups full` for steadier grids (~95 s with `--core`)
npm run harness:factions -w @raid/server -- --python   # faction cycle per weapon in the real sim vs testing/realtime.py (report only; also --mode full, --mode policy for moving fighters, --nmax N)
npx tsx packages/server/bench/stepBench.ts            # step() cost with 8 players and 60 mobs (gate: avg < 5 ms, p99 < 15 ms; test/perf.test.ts)
npx tsx packages/server/bench/bandwidth.ts [seed=N]   # bytes/s per client, headless with the real encoder: typical, heavy, idle (gate: < 20 KB/s; test/bandwidth.test.ts)
npx tsx packages/server/bench/mobDuel.ts              # real-sim duels of a starting player against every region's mob and elite (mob strength; see side-session notes / GAME_DESIGN 11)
python3 testing/test_rpsls.py                 # the faction design oracle (needs numpy); python3 testing/test_kite.py is the kiting guarantee at duel pace (~5 s)
```
Server env overrides (see `packages/server/src/config.ts`): `RAID_PORT`, `STASH_FILE` (the profile file; the name predates profiles v2), `MIN_PLAYERS`, `LOBBY_SECONDS`, `FILL_SECONDS`, `PATIENCE_SECONDS` (at 8 alive), `PATIENCE_MIN_SECONDS` (at ≤3 alive), `SUDDEN_DEATH_SECONDS`, `COLYSEUS_LATENCY` (simulated ms), `DUMMIES=1` (training dummies and a weapon rack next to every spawn), `MOBS=0` (no regional mobs: they are on by default, one at every camp spot).

## Layout
- `packages/shared` — TS source consumed directly (no build). Contracts + pure logic used by both sides:
  `constants.ts`, `schema.ts` (Colyseus state; import via `@raid/shared/schema`), `messages.ts`, `factions.ts` (faction sheet + damage law), `signatures.ts` (real-time signature numbers, matchup score, damage flash),
  `weapons.ts` (catalog, faction × weapon formula, timings), `interactions.ts` (shield/stagger/ball-vs-arrow rules), `policies.ts` (how to play each weapon: bots, harness, mobs),
  `buffs.ts` (S-curve stacks, combos, the feed reward curve, bounty stacks, drop stat), `mobs.ts` (the regional mob catalog: `mobFaction` = region faction scaled by `MOB_K`/`ELITE_K`), `buffView.ts` (the HUD's buff maths and wording), `fxCodec.ts` (the compact `fxs` wire form),
  `map.ts` (map types/helpers), `mapgen.ts`, `rng.ts`, `pathfind.ts`, `geometry.ts`, `interp.ts`,
  `cosmetics.ts` (the cosmetics catalog, slots and the packed `look` word), `achievements.ts` (achievement goals, pure).
- `packages/server` — `src/index.ts` (`defineServer`, HTTP API), `rooms/RaidRoom.ts` (thin adapter) and `rooms/FxChannel.ts` (builds each step's `fxs` batch), `sim/` (pure game logic;
  `arena.ts` owns the run lifecycle, `step.ts` the tick order), combat: `combatant.ts` (players and mobs as one thing), `weapons.ts` (state machines),
  `projectiles.ts`, `melee.ts`, `ledger.ts` (per-tick damage ledger), `factions.ts` (faction signatures: targets, engagement, chill, lifesteal), `mobs.ts` (training dummies), `mobLife.ts` (regional mobs: camps, damage taken, death and drops, regen), `mobAI.ts` (their inputs: idle/fight/return), `buffs.ts` (stacks on the player, kill combos, the barrier), `feed.ts` (feed, lobby median, mob reward multiplier, rampage announcements), `loot.ts` (weapon pickups);
  `persistence/ProfileStore.ts` (profiles v2: GV, stats, cosmetics; migrates v1 stash files),
  `bots/` (`BotClient`: a headless player that sends inputs only; `mobHunt.ts` its mob-farming rules; `runBots` is its CLI), `bench/` (step, bandwidth and mob duel measurements), `harness/` (headless weapon duels: `runHarness` CLI, matrix, report, parity with the Python model; `runFactionCycle` the faction cycle per weapon).
  Tests in `test/`; `e2e.test.ts` plays whole runs with four bots and mobs on (it plays a second run when the first shows no kill, signature hit or mob death by a bot, about 1 run in 20 for the mob death, and fails if the second lacks it too; every bot's room also decodes every `fxs` batch against its own roster, with no tuple lost).
- `packages/client` — `net/` (connection, clock sync, interpolation), `scenes/RaidScene.ts`, `render/` (2.5D projection; player, mob, projectile, fx and container views),
  `ui/` (DOM overlay: menu, HUD with the buff rows (`buffsHud.ts`), weapon bar, results).

## Architecture rules (do not break)
- **Authoritative server.** Clients send inputs only (`move`, `stop`, `aim`, `attack`, `release`, `swap`, `pickup`). Never accept positions, damage, or outcomes from a client. Apart from a walk target, the numbers it supplies are aim angles and a render time `t` (clamped to `MAX_REWIND_MS`).
- **Fixed 20 Hz tick.** Message handlers validate and enqueue; they never mutate game state. The sim consumes input queues at the start of each fixed 50 ms step.
- **Sim is pure.** `server/src/sim/*` must not import `@colyseus/core` or touch clients/sockets. It mutates the schema state + a non-synced runtime struct and returns events. The Room converts events into messages and persistence. Test the sim headless.
- **The ledger, one way down, one place to settle.** Every hit (projectile sweep, melee) is recorded in the per-tick damage ledger (`sim/ledger.ts`, `recordHit`) and applied all at once after melee: mitigated per victim, then `applyHits`/`applyDamage` for a player (`sim/arena.ts`) or `damageMob` for a mob. Sudden death calls `applyDamage` itself. Every exit from the fight (death, leave) goes through `downPlayer`. In-tick results come only from `settle()` at the end of the tick, so the shuffled input order never decides a winner: a fighter killed this tick still lands what it started, simultaneous hits on one victim land together and the kill goes to the largest rival hit, and simultaneous last deaths go to the higher hp fraction at tick start (an exact tie draws). **Spoils are paid after the pass:** while `applyLedger` applies damage (`world.combat.collecting`), a kill's GV, bounty, stacks, kill barrier, drops and combos are queued with `payLater` and run once every victim has taken theirs, from the lobby median feed as it stood before the pass, so a reward never decides who survives. Outside the pass (`applyDamage`, tests) `payLater` runs at once. A regional mob goes down through `hurtMob` (`sim/mobLife.ts`), a dummy through `damageMob`. A mob's kill goes to the player who did it the most damage over the whole fight (not whoever lands the last hit); a mob that finishes a player a rival hit within `KILL_CREDIT_SECONDS` credits that rival (kill GV and bounty), as leaving does.
- **Tick order is fixed** (`sim/step.ts`; do not reorder): inputs (players shuffled, then mobs) → weapon state machines → `afterWeapons` → movement → history → projectile sweep (present time, 10 ms substeps) → spawns → melee (rewound) → `beforeDamage` → ledger → systems → sudden death → settle.
- **Combat netcode.** Projectiles are announced once, in the `fxs` batch of the step that loosed them, and never updated (the synced state has none: they are plain objects in `world.projectiles`, and a client that joins or reconnects mid-flight is sent the ones flying as a batch of its own, `FxChannel.inFlight`, queued behind its full state by core): clients fly them from `(x, y, vx, vy, t)` and a `projEnd` fx says where and why they stopped. Melee samples the attacker and every target at the attacker's render time (`rewindT`). A projectile leaves from the shooter's rewound (drawn) position, and aim angles are measured from where the client draws its own player. Keep those three consistent.
- **Players and mobs fight through `Combatant`** (`sim/combatant.ts`): weapons, melee, projectiles and the ledger take either; only how they go down differs. A regional mob's faction is its region's scaled by `MOB_K` (elite `ELITE_K`) and paced, read through `factionOf` like a player's, so signatures, armor and timings apply to it unchanged.
- **Mobs are players who send inputs.** `sim/mobAI.ts` is a system (after damage): it pushes `move`/`aim`/`attack`/`release` into the mob's own `InputQueue` and step.ts applies them next tick through the same handlers as a player's. Idle mobs send nothing. A mob walking home (`return`) is evading: `hurtMob` returns 0, `factions.ts` gives it no signature target or contact, and it is whole when it arrives; it gives up 6 s after it last *dealt* damage, so kiting from outside its leash gains nothing. The coliseum teleport puts every mob back on its camp spot at full hp. Mobs never hurt each other (a hit is recorded with scale 0) and their shots fly past each other.
- **Buffs and the feed** (`shared/src/buffs.ts`, `sim/buffs.ts`, `sim/feed.ts`): stacks are fractional floats on `PlayerState` (`stacksHp/As/Ms`), the S-curve bonus feeds max hp (`syncMaxHp`), `attackInterval`/`damagePerHit` (via `attackSpeedMult`) and `world.moveModifiers` (`moveSpeedMult`). Combos at 3 and 5 stacks fire on every kill. The mob reward curve and the catch-up read the feed (`kills + 0.25 × mob kills`); the **bounty reads player kills only**.
- **Wire format.** All fx of a step go out as ONE `fxs` message (`shared/src/fxCodec.ts`, `rooms/FxChannel.ts`): integer tuples, fighters named by index into the append-only `RaidState.roster`, projectile launches in the same batch (`FxBatch.p`). Players still in the lobby are not rostered (no fx names one, and an entry is for good); a mob's index is rostered when it is placed. `unpackFx(batch, room.state.roster, onDrop?)` needs the roster: without it every id-bearing fx is dropped, and `onDrop` is how a skipped tuple is noticed (the client warns once in dev builds; the e2e run asserts nothing was dropped). The client holds `fxs` batches from the join until the scene starts (`net/fxInbox.ts`). Adding a field to an `FxEvent` means adding it to its tuple and to `test/fxCodec.test.ts`. Synced numbers are narrow on the wire (float32 positions/hp, uint32 timers); the server keeps doubles.
- **Signatures ride the ledger.** Faction bonus damage (burn, backlash, disease, mark) is recorded in the tick's damage ledger in the `beforeDamage` phase, so it lands with the tick's hits. Heals go through `heal()` in `sim/factions.ts` (3 s out-of-combat lockout; Holy's lifesteal exempt). `sim/factions.ts` stretches chilled fighters' `readyAt`, bow draw and press buffer every tick (not the ranged recovery): weapon timing changes must keep the chill working (`npm run harness:factions` checks it against `testing/realtime.py`). A landed stagger (the 0.5 s immunity starts) pauses the staggered fighter's burn, disease and mark for its weapon's windup (`staggerPause`; the real sim only, `realtime.py` has no staggers).
- **The shop is server-only.** Purchases and equips are `POST /api/profile/:name/purchase|equip` with the profile token; the client sends only a cosmetic id (and a slot). `ProfileStore.purchase/equip` check the token, the catalog price, ownership and the balance in one synchronous step (no `await` between check and change), so a double spend is impossible. Spending lowers `gv` only, never `gvLifetime` or `gvByMonth` (the leaderboard ranks GV earned). Achievements are evaluated inside `recordRun`; an id lands in `achievements` once and its reward cosmetics are granted in the same step. Win achievements and the per-faction/weapon counters count only `winQualified` wins (the win-bonus gate: `!winBonusWithheld`), so a walkover against a throwaway callsign earns nothing; kill and bounty achievements are not gated (their rewards are unpriced; an owner decision). The leaderboard ranking is cached per month (dropped when GV is credited in it), and `you` on `GET /api/leaderboard` is sent only with that profile's own token. Equipped cosmetics reach other players as one synced `PlayerState.look` word, fixed at join.
- **GV banks at resolve.** The sim only accumulates run GV and reports it in `resolved` results; the Room banks it (`recordRun`, or `bankGv` for a run voided by shutdown). Run gear never persists.
- **The map is never synced.** Only `seed` is in state; both sides call `generateMap(seed)` (must stay deterministic: use `rng.ts`, never `Math.random`, in shared). Loot contents are rolled server-side with a non-public RNG.
- **Clients render in the past.** Remote and local entities render at `serverNow − INTERP_DELAY_MS` via `SnapshotBuffer` (shared/interp.ts). No client-side prediction yet.
- **Rendering is separate from logic.** Phaser scenes only read interpolated state and send inputs. Projection lives in `client/src/render/projection.ts` (screenY = worldY · Y_SCALE, height drawn upward, depth = worldY).

## Conventions
- Colyseus 0.18 APIs (not 0.15/0.16 tutorials): `defineServer/defineRoom` from `@colyseus/core`, `Room<{ state: X }>`, `messages = { ... }` or `this.onMessage`, `setSimulationInterval`, `client.sessionId` (no `client.id`), client `@colyseus/sdk` + `Callbacks.get(room)`.
- Schema uses the decorator-free `schema({ ... }, "Name")` + `t.*` builders. Give primitives `.default(...)`. No decorators anywhere.
- Only the server imports `@raid/shared/schema` at runtime; the client uses `import type` from it (it decodes by reflection).
- All tunables live in `shared/src/constants.ts`, `weapons.ts` or `factions.ts` (mob scale, leash, buff curves and the reward curve are in constants.ts). Units: world units (1 tile = `TILE` = 32), seconds for durations unless a name ends in `Ms`, server time in ms.
- Weapon numbers live in `shared/src/weapons.ts`: the v3 faction × weapon formula (a weapon is a % boost on the faction's rate; `attackInterval`, `damagePerHit`, `backlashPerSwing`). It must keep matching `testing/realtime.py`: `python3 testing/weapon_reference.py` prints the reference tables, pasted into `shared/test/weapons.test.ts` and `server/src/harness/parity.ts` when the design numbers change. `DUEL_PACE` (2) multiplies every faction damage number (not hp; Sentenced's mark ramp by k²) through `pacedFaction`; sim combat reads the paced sheet through `factionOf` (`sim/combatant.ts`), never the raw one.
- Design rules the sheet left open are recorded in `docs/GAME_DESIGN.md` 9.4. Change them there and in the tests together.
- No `Math.random` in shared code. No enums or decorators (keeps tsx/Vite/TS7 happy).
- Keep comments sparse; explain *why*, not *what*.

## Known TODOs (keep this list honest)
- Weapon tuning (9.1, `testing/TUNING_9_1.md`): bow 240 u and wand 220 u against `MAX_SIGHT_CORRIDOR` 480. Mapgen's cover and spawn screens are certified for 480, now twice the bow's range; relaxing them is an owner decision. The kite check's margin is 1.16 (Fire > Plague with the bow, the axe the weakest melee weapon: 1.23 s of tolerance against 1.06 s of free fire; real kiting costs at most x1.12), so a longer bow or a lower melee number is tested against it. The ranged move multipliers are 0.1 on purpose (nearly a root). The harness's KITING section and `testing/test_kite.py` guard the kiting guarantee; `python3 testing/weapon_reference.py` regenerates the parity tables (`weapons.test.ts`, `harness/parity.ts`) after any weapon number changes.
- Interest management: everyone receives every player's weapons, every container's contents, every mob and every projectile, wherever they are. Plan: `StateView` + `.view()` fields, per-client add/remove by distance each tick.
- Facing is synced for everyone at up to 20 Hz per player (every `aim` input patches `facing`, and `maxMessagesPerSecond` is 100 to allow it). Part of the same interest-management work; a per-client view would cut it.
- No client-side prediction for the local player (0.18 has `Predict`/`room.input()` if needed).
- Single process only: the "profile already in a raid" guard and the stash file are process-local.
- No rate limit on matchmaking (it does verify the profile token before creating a room or reserving a seat, via the static `RaidRoom.onAuth`).
- HP/status/containers/timers render at the latest patch while positions/fx are 100 ms behind (deaths are held back to match).
- Lag compensation (melee rewind and the shooter's drawn position) trusts the client's `t` anywhere inside `[now − MAX_REWIND_MS, last published tick]`. A cheating client can pick the most favourable `t` in that 300 ms window (a wand ball can come from up to ~500 ms back: its origin is taken when the cast starts and it leaves 0.2 s later). Mitigation: bound `t` per client by measured RTT, or require it to be monotonic.
- `MAX_REWIND_MS = 300` fully covers clients up to ~150 ms RTT (render delay 100 ms + RTT + one tick). Beyond that, swings at moving targets start to miss (projectiles fly in present time and are not rewound).
- GV banks when a player's run resolves. A graceful shutdown (SIGTERM/SIGINT, uncaught exception) pays the GV earned so far; a hard kill (SIGKILL, power loss, OOM) mid-run loses it.
- Gates: the server's `collisionMap(world)` returns `withGates(world.map)` while `state.gatesLocked`, so movement, line of fire and loot line of sight are sealed. `coliseumSpots` hands out mapgen's coliseum inner spawns. Sudden death still hits everyone standing while locked.
- Room creation blocks the event loop: `RaidRoom.onCreate` calls `generateMap` synchronously. A map costs about 17 ms on average (worst case reaches about 96 ms on seeds that need 4-5 attempts, e.g. 732, 2547, 3129), roughly 9x the old generator, and the first map on a process takes about 70 ms because it also builds the lane tables (about 17 MB, kept for the process), on the client too. Mitigation: generate off the event loop (worker) or pre-generate the next seed.
- Spawn walking distance is uneven: spawns within `MAX_SIGHT_CORRIDOR` of each other are screened against the sim's ranged hit cone (every aim ray passing within `RANGED_HIT_REACH` of the other's centre meets a wall first), but walking distance from spawns to the coliseum centre varies a lot (max/min per map is 1.54 mean, 3.07 worst). The owner's target is 1.2. Meeting it needs spawn selection reworked around walking-distance targets.
- Sight corridors narrower than one tile are not capped. Mapgen guarantees the 480 u limit for 32 u strips only; 24 u strips measured up to 473 u and 16 u strips up to about 580 u. A 24 u gap holds a player (`PLAYER_RADIUS` 12). The owner deferred guaranteeing these.
- GV can be farmed with free callsigns: the win bonus needs 3+ starters and damage on 2+ different opponents (WIN_BONUS_MIN_*), but two throwaway callsigns that get killed still pay kills and the bonus. Bounties are uncapped but come from player kills only (an owner decision: mob kills feed buffs, mob GV and the reward curve, never the bounty), so a partner can only cash a bounty that real kills built. Mob GV is capped at `GV_MOB_CAP` per run.
- GV earned after a player's result went out is dropped (`awardGv`). A projectile outlives its owner and its hit still lands; a kill by a shooter who left or whose result is out is credited by name only (`killedBy`), with no GV and no bounty.
- A player who joins without picking a faction (old clients, bots without `--faction`) gets the round-robin default by join order (`defaultFaction`); a failed join or a lobby leave still uses up a slot.
- `SIGNATURE_WEAPONS`: Sentenced stays on the bow (measured, a best-guess decision for the owner to overrule). In the real sim (policy mode) Sword > Wand decides Holy > Sentenced when Sentenced starts on the sword (Holy wins 0 of 18 setups) and the axe fails it too (78% win, worst HP 0.0%); the bow holds all four of Sentenced's openings (worst 24.7%, Holy > Sentenced). Details in `testing/TUNING_10.md` section 7 and `GAME_DESIGN.md` 10.1.
- The weapon edges hold (10 of 10) against a straight melee charge and against the harness's melee `weave` (55 degrees off the line, a new side every 0.4 s) and `jink` (50 degrees, every 0.3 s). Bow > Axe needed the axe at 0.77 for that (82% against the jink, 44% at 0.8): the window is 0.76-0.77, because 0.75 and below break Axe > Wand and 0.78 and above thin Bow > Axe's Frost column. A faster arrow (1100-1300 u/s), a longer axe root and the bow's draw were measured and did not help. The Fire column stays thin (Bow > Axe 11% against the jink and 44% against the weave, Bow > Sword 33% against the jink, Wand > Shield 11-22%): hit-count cliffs of a 500-HP faction, so only a faction number (Phase 10) or a leading projectile would move them (`testing/TUNING_9_1.md`, L6 and "Against a weaving melee approach"). Shields still shut out sword and bow at 100% hp (Shield > Sword and Shield > Bow end with the shield untouched), and Wand > Bow is thin in the Frost column against a strafing bow (22%).
- The plan's "HP scale 550–2000" was not applied: the faction sheet's 500–1750 is used.
- Same-faction weapon edges flip with signatures on (owner decision, nothing retuned): in a Fire mirror Sword > Axe goes 100% to 0% and Sword > Wand to 11%; in a Sentenced mirror Sword > Axe, Sword > Wand and Axe > Wand go to 0%, because its damage is almost all the mark times the weapon's dpsMult. The weapon harness runs with signatures off by default. `testing/TUNING_10.md` section 8.
- Lifesteal counts the whole hit, including overkill on a killing blow of a PLAYER and hits on training dummies that refill. Kept for parity with `testing/realtime.py`, which counts it the same. Regional mobs are capped: what lifesteal feeds on is the hp the hits removed (`ledger.ts`, `landedShare`). A lifesteal cap above 100% is not an option: it stalls Holy against Holy (`testing/TUNING_10.md` section 2).
- Lifesteal is applied after the tick's damage, so on Holy's death tick its same-tick heal can't save it (`testing/realtime.py` nets the two). It only shortens fights Holy loses; the harness reports it.
- Signatures need a trade: a hit or block between the pair within `ENGAGE_TRADE_SECONDS` (3 s), so a bow-range DoT faction (Sentenced, Plague) kiting a melee chaser keeps its signature with one shot every 3 s. DUEL_PACE 2 halves every kiting tolerance in testing/COUNTER_REVIEW.md while free-fire time (set by range and move speed) stays the same. Owner decision.
- `tieRank` (sim/world.ts, the target choice between equal hits) is keyed on the same secret `orderSalt` as `actionOrder`. A client that stages about 32 ties and reads the outcomes (brand/sig) could brute-force the salt (2^32) and predict same-tick item races. A separate salt would shift `world.random`'s sequence, so it waits for a reason.
- Meta layer: the shop and equip endpoints have no rate limit (like profile creation), and a purchase is answered once it is in memory, before the file write lands: a hard kill in that window undoes the purchase together with its GV debit (the file is a consistent snapshot), never one without the other.
- Meta layer: "bounty claimed" counts runs that paid bounty GV (`progress.bountyRuns`), not individual claims. There is no end-of-month trophy job: the leaderboard keeps each month, and nothing is awarded when a month closes.
- Profile creation has no rate limit or cap: any client can `GET /api/profile/<new name>` as often as it likes, and `/api` answers every origin (`Access-Control-Allow-Origin: *`) so any web page can do it. Each claim adds a profile and a file rewrite.
- Mobs (Phase 11): strength and spacing were measured with one scripted player per duel (`bench/mobDuel.ts`), never with humans or camp-mates: expect playtests to move `MOB_K` (0.45), `ELITE_K` (0.65) and `MOB_LEASH_RADIUS` (9 tiles). Known holes: a Frost shield starter cannot finish a Frost shield mob (both block), so the second weapon is the answer (owner decision pending); a chasing mob's swing hits every standing player in its arc, so a player can drag an elite onto someone who never touched it (the leash limits it); a Sentenced mark built on a mob restarts after each give-up (an evading mob has no signature target); a wand mob cannot hit a player standing on top of it (a ball that starts inside a body only hits if it heads into it, Phase 9); a retreating shooter drags a melee mob to its leash, where it evades and heals, so a ranged starter must burst a melee mob down inside one round.
- Mob kills do not feed achievements yet (owner question). Buff stacks, combos and the feed reset every run; nothing persists.
- Bandwidth gate: heavy load (8 camps fought at once, ~33 mobs fighting) measures 14.1-16.3 KB/s over seven seeds, typical 9.1-10.5, against 20 (ws payload only; TCP/TLS framing adds a few KB/s). The margin is about ±1.5 KB/s of sim drift; StateView (Phase 13) is still the real fix for larger rooms.
