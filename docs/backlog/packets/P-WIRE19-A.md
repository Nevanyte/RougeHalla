## 1. ID and outcome

Protocol 19, part 1. When this packet lands:

1. **Native card ids on the wire.** `WireRewardId::Card(id)` admits the whole `CardId` index space: the 80 catalog cards
   (0..=79, `CardId::ALL`) and the 14 natives (80..=93, `CardId::NATIVE`, P-AUG-NATIVE-1a). The encoding stays one byte
   (`kind 1, u8 id`); only the bound moves from `< 80` to `< 94`. Card 94 and above is refused by every decoder and by
   the encoder (atomically, as today). `WireBuild.cards` stays the 80 catalog counts (native counts are P-WIRE19-B's
   readouts, never a build entry).
2. **The first-pick window on the chest.** A reward chest row gains one trailing field, after `can_choose`:
   `first_pick: Option<WireFirstPick { until: f64, mine: bool }>`. It is `Some` exactly while the chest's killer
   first-pick window is in force (P-ELITE-PICK-1: `server_time < until` and the killer still standing), for every viewer
   who sees the row; `until` is the window's end in server ms (public); `mine` is true only in the killer's own row.
   Nobody else learns who the killer is (decision 2).
3. **The restriction lifted.** P-AUG-NATIVE-1a's `check_world` refusal of a native chest option
   (`crates/rh-sim/src/cards/native/mod.rs:230-238`) narrows to the Legacy table: a **Rework** world's chest may offer a
   native card (it restores); a **Legacy** world's may not (decision 4). Pools are untouched (decision 5).
4. **Identities.** `PROTOCOL_VERSION` 18 → 19 (`crates/rh-protocol/src/lib.rs:208`); `OBSERVATION_VERSION` moves past 30
   (`crates/rh-sim/src/observe.rs:28`: `RewardChestView` gains `first_pick`); `POLICY_CONTRACT_VERSION` moves past 25
   (`crates/rh-policy/src/lib.rs:56`: the projected State key 4 changes). The next numbers are 31 and 26 unless
   P-AUG-NATIVE-1b takes them first (section 2).
5. **Every decoder:** Rust (`rh-protocol`), C# (`client-unity/RoguehallaNet`, Unity copy by `bash client-unity/sync-net.sh`),
   JS (`crates/rh-server/web/probe.html`, checked by `tools/protocol-js/` and `tools/unity-browser-reload-proof/`).
   `protocol/fixtures/v19.json` is generated by `cargo run -p rh-protocol --bin protocol-fixtures`; `v18.json` stays as
   history. A protocol-18 client is refused with `RejectCode::ProtocolMismatch` ("server speaks protocol 19, client 18");
   a protocol-19 client refuses an 18 Welcome.

### Decisions (asked of this brief; decided and pinned by the oracle)

1. **Encoding of native ids: widen the bound, keep the byte.** `Card(u8)` already carries any byte; 94 card ids fit. A
   separate reward kind for natives would split one id space in two and make every reader map twice. The rule is
   "index into `CardId::ALL` then `CardId::NATIVE`" (catalog 0..=79, native `80 + i`), the same index
   `CardId::index()` returns. A later native card is another bump of the bound (and of the protocol).
2. **The killer's id is not public.** The coordinator's note assumed "the killer is credited publicly at the kill". It is
   not, in Rust: `Event::CampCleared { camp }` (`crates/rh-sim/src/events.rs:46-48`, `Visibility::Everyone` at `:265`)
   names only the camp; no event, toast or State item names a mob's credited killer; the one per-viewer player id on a
   chest row, `taken_by`, is shown only when that player is the viewer or visible to them
   (`crates/rh-sim/src/reward_chests/observer.rs:126-138`). So the wire carries the window's **end** (public, as the
   chest's own `expires_at`) and a per-viewer **`mine`** flag (true only for the killer, like `can_choose` an own-only
   fact), never an id. That is all P-AUG-UI-2's countdown needs ("Your first pick 3 s" / "First pick 3 s").
3. **The field is shown only while the window is in force** (`server_time < until` and the killer standing, the same
   facts `first_pick_blocks` reads, `crates/rh-sim/src/reward_chests/mod.rs:84-90`). A window that ended early (the
   killer died, was downed, resolved or left) or ran out is `None` at once, so no client counts down a window that no
   longer gates anyone. It is part of the row's public identity (`public_cmp`, `observer.rs:248-280`), so the killer's
   row is republished when it ends even though the killer's `can_choose` does not change.
4. **The native chest rule narrows, it does not vanish.** Under `AugmentRule::Rework` a chest may offer a native card;
   under `Legacy` it may not (natives are outside the Legacy card table, as the count rule at
   `cards/native/mod.rs:201-206` already says for builds). Camp chests are still bound to the pool by
   `reward_chests::validate_world`'s `pool.contains` rule (`mod.rs:490-494`), so nothing changes for them until a pool
   admits a native.
5. **Pool admission is not this packet's.** P-AUG-NATIVE-1b keeps native pool admission switched off until WIRE19-A
   lands. WIRE19-A removes the reason (natives can be shown) and nothing else: no pool, offer rule or draw changes here.
   The switch is flipped by whichever packet first needs natives offered (1b if it merges after this one, else the first
   batch packet), with this packet in its base. Until then no live chest offers a native card.
6. **Room for P-WIRE19-B.** The readout rows are a new State key (14, after `BuildSummary` = 13) appended inside protocol
   19: WIRE19-B regenerates `v19.json` again and needs no second bump **provided no build of WIRE19-A alone is deployed**
   (a WIRE19-A client refuses an unknown State key, `tests/state.rs` "unknown key"). If one is, WIRE19-B bumps to 20.
   This packet adds no key, no readout and no `observe.rs` code beyond the version constant.
7. **Version pins of other packets' tests are the implementer's mechanical moves** (listed in section 5, as
   P-PROTOCOL-18-STAMP-1 did), not oracle amendments: the observation and policy numbers depend on the merge order
   with P-AUG-NATIVE-1b, so this oracle asserts only that they moved past 30 and 25. Expectations that change in
   behaviour are amended by this oracle (`oracle-amend:` commits, listed under "Oracle files").

### Wire layout (State key 4, one row; new bytes in bold)

`varint handle, u16 x, u16 y, f64 expires_at, u8 n (≤3), n × option, u8 picked, u8 can_choose,` **`u8 tag (0|1)`,
then if 1: `f64 until, u8 mine (0|1)`**. Option: `u8 kind; kind 1: u8 card id < 94; kind 2: u8 boost < 8; kind 3: u8
key, f64 gain;` then `u8 taken, opt varint taken_by` (unchanged). A row is valid when, beyond today's rules, `until`
is finite and `until <= expires_at` (the chest outlives its window: `validate_world` keeps `until <= drop + 5 s` and
`expires_at = drop + 15 s`, `reward_chests/mod.rs:101, 513-519`).

  native options); no checkpoint layout changes, so no `CHECKPOINT_FORMAT` bump.

## 11. Known traps

- **Trailing byte on every row.** The `00` tag is written on every row, window or not. `WireRewardChest::len()`
  (`reward.rs:107-115`, `+ 15` today) grows by 1, or 10 with a window; `encoded_len` is checked against the bytes.
- **The malformed card vector** (`samples.rs:4436-4446`) patches the byte after `[1, 79, 0, 0]`; with the new trailing
  tag the `rposition` still finds it, but the patched value must be 94, and the name `state_reward_card_id_94`
  (the three decoders' maps already expect it: oracle-amend).
- **`mine` is per viewer**, like `can_choose`: compute it from the observer's own `viewer`, never from a shared row.
- **`public_cmp` must compare `first_pick`** (decision 3), or the killer's row lags the window's end by up to 20 ticks.
- **Scene candidate**: `scene_candidate/mod.rs:26` and `SceneCandidate.cs:17` both move to `14 | 19`, or every
  scene-candidate limit check refuses.
- **The probe marker** `// ---- protocol v18 ` is matched literally by `normal-companion.mjs:22` and
  `normal-companion.test.mjs:13`; the `check-*.mjs` and the new oracle use a `v\d+` regex.
- **Bots** read the projected rows (`perception.rs`); a native option must read as its name (`markedMan`), never `""`.
- **C# enum cast**: `(CardId?)o.Id` (`Collections.cs:459`) of 80..=93 is an undefined `CardId` value until P-AUG-UI-2
  adds display rows; the codec must not refuse it.
- **The Trophy reference JSON**: `check-vectors.mjs` compares the probe's decoded `state_trophy_reward_keys` rows to the
  Rust `decoded` JSON (`samples.rs` `decoded_trophy_state_json`, `:7684`): that row string must end in
  `"firstPick":null` (or the window), or the JS step fails although the bytes agree.
- **Other crates** only read `RewardChestView` (`rh-headless/tests/cards.rs:50`, `examples/first_playable.rs:41`); no
  literal outside the four oracle crates needs the new field (checked at the stub).
- **Content hash**: unchanged (no content row). The hash tape's `observationVersion` moves with the constant; re-record
  it by its command only.
