(`docs/MIGRATION.md:200-206`: a client built before that batch sends the same protocol number and then refuses every
Welcome on "hud term count"). This packet moves the protocol number to 18 and nothing else: `PROTOCOL_VERSION` is 18 in
`crates/rh-protocol/src/lib.rs:196`; `protocol/fixtures/v18.json` is generated by

commit accept each other; a protocol-17 client is refused by a protocol-18 server with `RejectCode::ProtocolMismatch`
(`crates/rh-server/src/conn.rs:124-135`), and a protocol-18 client refuses a protocol-17 server's Welcome
(`client-unity/RoguehallaNet/Net/Session.cs:583`: `Fail("server protocol " + w.Protocol)`); a protocol-17 server
refuses an 18 Hello by the same `conn.rs` envelope check it already has.

### How "no wire byte changes except the version" is proven

Measured on this base (a scratch run with `PROTOCOL_VERSION = 18`, output moved out of the tree, nothing committed):
the generated v18 manifest differs from `v17.json` on exactly 136 lines, and **all** of them are explained by these
four substitutions applied to `v17.json` (after which the files are byte-identical):

1. the header `"protocol": 17,` becomes `"protocol": 18,` (1 line; `samples.rs:7783`);
2. a vector whose `hex` begins `011100` (a Hello: tag `0x01`, then the version u16 LE) begins `011200` (3 lines);
3. a vector whose `hex` begins `811100` (a Welcome: tag `0x81`, then the version u16 LE) begins `811200` (132 lines,
   including the hand-built Welcome frames of `samples.rs:3627`, `:3730`, `:4260` that write `PROTOCOL_VERSION`);
4. a `debug` string's `protocol: 17,` becomes `protocol: 18,` (17 occurrences, inside lines already counted).

`v17_and_v18_differ_only_in_the_version` in the oracle applies exactly these and asserts equality, so any other byte
change fails it. Hex lengths are unchanged (u16 either way).
