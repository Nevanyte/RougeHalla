## 1. ID and outcome
Two legacy world marks cannot be drawn because their facts are not sent.
- **Patience range:** legacy outlines, for every living camp, the tiles of the camp's territory from which its mobs
  still chase (`campPatienceOutline`: tiles of the territory grid where `leashOk` holds for at least one rest spot;
  `packages/client/src/render/CampPatience.ts:18-50`, `packages/shared/src/mobs.ts:243-262`: `camp.area`,
  `min(camp.radius, MOB_LEASH_CAP)`, `MOB_LEASH_RADIUS`, with a fallback circle when the camp has no territory). The
  client has only each camp's position and clearing radius. The map blob gains a **patience plane**: one byte per tile,
  0 or the 1-based index of the camp whose patience range covers the tile, computed once by the server with the sim's
  own leash rule, run-length encoded like the other planes. It is public map data (legacy clients computed it).
- **Quest carrier:** the quest row names its carrier by a view-local roster id that the client cannot map to a
  fighter. The row gains the carrier's **public actor id**, present only while the viewer may see that fighter
  (C-OBS), absent otherwise.
Still protocol 17, `v17.json` regenerated; the C# client exposes both (`MapBlob.Patience`, the quest row's carrier
actor). Drawing them is `P-UNITY-WORLD-MARKS-2`.

## 6. Contracts and references
- C-OBS: the carrier's actor id is sent only when that fighter is in the viewer's delivered actors this tick.
- The plane is derived from the map and content only; it is the same for every viewer and does not enter
  `content_hash` unless map sections already do (say which).
- Wire rule in `AGENTS.md`: Rust, C# and JS decoders pass the regenerated vectors in one branch; refusal vectors.

## 7. Behaviour to preserve
- Every existing vector round-trips; a map blob without the plane still decodes (the section is optional).

## 8. Acceptance checks
- Golden vectors: a blob with the patience plane; a quest row with and without a carrier actor; refusal of a plane of
  the wrong size and of a camp index past the camp count.
- One sanity test: on the seed-1 map, a tile at a camp's centre carries that camp's index and a tile two leash radii
  away carries 0; the plane agrees with the sim's leash predicate on 100 sampled tiles.
- "A viewer who cannot see the carrier receives no carrier actor id."
- `scripts/gate.sh --oracle packet/P-WIRE17-MAP-2 --regen-fixtures` passes.

## 11. Known traps
- More than 255 camps cannot be indexed in a byte: assert the camp count at encode and refuse.
- Overlapping patience ranges: legacy draws each camp's outline; one byte per tile keeps only one camp. If ranges can
  overlap on generated maps, say so and use a bit plane per zone or a u16 mask instead (decide in the oracle).
