## 1. ID and outcome
Legacy shows, and Unity cannot yet: the stat reward each camp gives (badges on the Tab map and over living camps), ward
beacons with ownership and seconds left, the top-left GAINED strip (nine values plus farmed mob bonuses) and the
bottom-left champion panel (per-hit damage split, attacks per second, passive numbers). Unity may not recompute combat
numbers, so the server must send them. When this lands, still as protocol 17: each camp row carries its reward (stat
and amount) and a ward verdict (none, yours, another player's) with its expiry; the weapon table carries each weapon's
scaling terms; and the owning player alone receives a build summary (the values from `rh_sim::build_summary`, the
held-weapon hit split and attacks per second, the faction passive numbers, the Fire roam charge).

**Split (oracle author, 2026-11-11):** this packet is (a) camp reward and ward verdict per camp row and (b) the GAINED
part of the owner build summary (nine values plus mob-bonus rows). The champion panel values (hit split, attacks per
second, faction passive numbers, Fire roam charge) and (c) the weapon scaling terms in the Welcome weapon table moved to
`P-WIRE17-HUD-2` (docs/backlog/packets/P-WIRE17-HUD-2.md). Reason: (a)+(b) alone touch observe, projection,
collections, state codec, samples, the C# codec/collections/views and the JS decoder; with (c) and the panel the diff is
well past 400 lines. Paragraphs below that still mention the panel or weapon scaling describe HUD-2, not this packet.

## Decided layout (oracle author; the tests pin it)

### Observation (rh-sim, `observe.rs`; types already stubbed)
- `Observation.camp_hud: Vec<CampHudView>`: exactly one row per `Observation.camps` row, same order. `CampHudView {
  reward: Option<CampReward>, ward: WardVerdict, ward_expires_at: f64 }`.
  - `reward` = `Farm::reward_of(camp.mob_type)` mapped to `CampReward { stat: HudStat, amount: reward.value }` (the camp's
    regular mob type; elites are a separate badge). Map: Flat(Ad)->Offense, Flat(Ap)->SoulOffense, Stat(Damage)->Damage,
    Stat(AttackSpeed)->AttackSpeed, Stat(Lifesteal)->LifeSteal, Stat(MaxHp)->Health, Flat(Armor)->Defense,
    Flat(Shield)->SoulDefense, Stat(MoveSpeed)->MoveSpeed.
  - ward: from `MobRuntime.life[i]` (`CampLife.ward_owner`, `ward_expires_at`). Live iff `ward_owner.is_some() && now <
    ward_expires_at` (`now` = `sim.server_time()`), exactly the legacy draw test and the `WardSight` clause in
    `vision.rs:287-294`. Live and owner == viewer -> `Yours`; live and anyone else (including an unseated viewer) ->
    `Other`; otherwise `None` with `ward_expires_at = 0`. When not None, `ward_expires_at` = the raw expiry.
  - Do not touch `CampRoster` (checkpoint state, `deny_unknown_fields`) or `PublicSnapshot.camps` (`observe.rs:1212`).
- `Observation.summary: Option<SummaryView>` = `build_summary(sim, viewer)` mapped to `SummaryView { gains: [f64; 9],
  mob_rows: Vec<SummaryMobRow> }`; `gains` in HudStat order (offense, soul_offense, damage, attack_speed, life_steal,
  health, defense, soul_defense, move_speed), unrounded; `mob_rows` the `Some` slots in catalog order with the stat mapped
  as above. `None` for an unseated viewer. Built only from the viewer's own player: C-OBS.
- `OBSERVATION_VERSION` 24 -> 25. Reuse buffers in `observe_into` (clear and extend) so steady-state observation does not
  allocate more than today.

### Wire (rh-protocol `state.rs`; types already stubbed). All integers little-endian.
- `HUD_QUANTUM = 1e-4`. Quantize `q(v) = (v / HUD_QUANTUM).round()` (Rust `f64::round`, half away from zero). A
  non-finite value or one outside the field's integer range is refused by the projection (EncodeError), never clamped.
- HUD stat code = `HudStat` variant index: 0 Offense, 1 Soul Offense, 2 Damage, 3 Attack speed, 4 Life steal, 5 Health,
  6 Defense, 7 Soul Defense, 8 Move speed. Units: GAINED values 2,3,4,8 are fractions, 0,1,5,6,7 are points; a camp
  reward or mob row uses its farm row's unit (Health there is a fraction of max hp, the four flat stats are points).
- `WireCamp` (State key 6): the existing bytes unchanged, then appended:
  - `reward` u8: 0 = none, else `1 + stat code` (1..=9); then, only when not 0, `amount` u16 = q(reward value), must be
    > 0.
  - `ward` u8: 0 none, 1 yours, 2 another player's; then, only when not 0, `expires_at` f64 (server ms), finite, >= 0.
  - Row length 19 + varint(alive) + 1 + (2) + 1 + (8). Max-camps frame grows by 12 x 512 bytes: still under
    `MAX_SERVER_FRAME`.
- New State key 13, `StateItem::BuildSummary(Option<WireBuildSummary>)`; `MAX_STATE_KEYS` 12 -> 13; owner-only.
  - payload: present u8 (0/1, anything else refused); when 1: `gains` 9 x i32 (q of each GAINED value, in code order);
    `count` u8 <= `MAX_SUMMARY_MOB_ROWS` (20); `count` rows of `mob_type` u8 (< 30, strictly ascending), `stat` u8
    (< 9), `stacks` varint u32 (>= 1), `total` i32 = q(row total).
  - Encoder and decoder refuse > 20 rows (`EncodeError::TooMany { what: "summary mob rows", n, max: 20 }`), unordered
    or duplicate mob codes, stat >= 9, stacks 0, mob >= 30. A stacks count above u32::MAX is refused by the projection.
- Delivery (`collections.rs`): the summary is compared and re-sent like the other reliable items, on the quantized
  `WireBuildSummary` (so an hp-dependent life-steal wobble below one quantum sends nothing); a full state carries keys
  1..=13. `frame.rs`: `seen` covers key 13; `Frame14` stores and exposes the summary.
- `samples.rs`: the max-size state sample carries a reward and a ward on every camp and a 20-row summary; add a typical
  summary sample; move the negative vectors `state_unknown_key` (key 13 -> 14) and `state_too_many_keys` (13 -> 14).
- C# and JS decode the same bytes and expose: per camp `reward` (stat code, amount), `ward` (verdict, expiresAt), and the
  owner summary (nine gains, rows). Keep the quantized integers plus a scaled double accessor; no recomputation.

### Identities
- Move: `OBSERVATION_VERSION` 24 -> 25; `POLICY_CONTRACT_VERSION` 18 -> 19 (projection gains fields; bots do not use them).
- Do not move: `PROTOCOL_VERSION` (17), `CHECKPOINT_FORMAT`, `REPLAY_FORMAT`, content hash; no sim state, schedule row or
  RNG draw changes, so every fixture's state hash is unchanged.

### C-OBS
- The summary is computed from the viewer's own `Player` only and travels only in that seat's State; the observation
  test proves seat B observes its own (different) summary and an unseated viewer none.
- A ward travels as a three-state verdict relative to the viewer, never the owner's id (legacy synced the owner id
  room-wide; this is narrower, not a deviation in what is drawn).
- A camp's reward is content (the same farm table for everyone), public as in legacy.
