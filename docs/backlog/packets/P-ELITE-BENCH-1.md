## 1. ID and outcome
`camp_bench --elite` (build with `--features elite-bench`) puts one fighter, carrying a build sampled from a bot at minute 5 of a live soak match, against each elite camp (10 kinds: 2 per zone), for every faction x weapon x seed, under `SimConfig::live_content()` (augments and elites `Rework`). It prints a JSON report on stdout and a readable death-rate table on stderr: per elite camp and overall, a solo death rate and a sample count. A second command, `camp_bench --sample-builds`, writes the checked-in sample `tools/balance-camps/minute5_builds.json`. The bench changes no rule and no number; the existing non-elite output is byte-identical.

### Design the oracle fixes (the implementer must not deviate)
CLI (flags after the program name; `run(args)` in `elite_bench.rs` is the whole mode minus the process):
- `--elite` plus `--quick`, `--seed S` (first seed, default 1), `--seeds N` (default 10; quick default 1), `--max-ticks N` (default 1800), `--builds PATH` (default `SAMPLE_PATH`, relative to the repository root), `--control-bare` (skip the build; negative control, report `"control":"bare"`).
- `--sample-builds [--seeds A..B]` writes the `SampleFile` JSON to stdout (default `1..21`; the implementer picks the range so the file has comfortably more than 8 builds and reports the numbers).
- Seeds: seed `s` is both the map-roll seed (probe world picks the camp, as `camp_bench`) and the world seed. Cell order: faction, weapon, elite kind (catalog order, zones in `FactionId::ALL` order), seed innermost. Quick: Frost,Holy x Sword,Wand x the first zone's 2 elites. A seed that rolls no camp of that elite is listed in `skipped` (same fields faction/weapon/kind/seed), never dropped and never an error.
- Build of a cell: `build_index = ordinal % builds.len()` where `ordinal` is the cell's position in the full inventory order including skipped cells.
- Report JSON: `version 1`, `mode "elite"`, `quick`, `max_ticks`, `config "live_content"`, `rules {elites:"rework", augments:"rework"}`, `solo true`, `caveat` (contains "Brawler"), optional `control`, `builds {source, tick:6000, count}`, `cells[]` (`faction weapon kind zone elite:true seed camp build_index build_applied_tick:0 start_dist outcome ticks first_hit_tick|null hp_start hp_remaining damage_dealt damage_taken`), `skipped[]`, `per_camp[]` (`kind zone samples deaths death_rate|null`, catalog order, one row per kind of the run), `overall {samples deaths death_rate|null}`. `outcome` is `died`/`cleared`/`truncated`; `hp_remaining` is exactly 0 when died. Table (stderr): the caveat line, one line per camp with its kind id, sample count and `{:.1}%` rate, an `overall` line, and the owner target (10-20%).
- Config: `SimConfig { ..SimConfig::live_content() }` with only the bench's own overrides the existing `config()` makes where a lone fighter needs them (`min_players: 1`, short lobby); the oracle checks the source mentions `SimConfig::live_content()`. Keep the Rework rules; say in the README which overrides were made (regen, quests, lifecycle) and why.
- The sampler: 8 `HumanBot` seats as `source_soak.rs`, `live_content()`, read every seated bot's cards (`build.counts()`), boosts and farm stacks at tick 6000. A match that ends before 6000 contributes nothing and is listed in `ended_early`.

## 12. Revision 2026-11-19: banked-camp builds (governs over 1, 8 and 11 where they differ)

### Why decision 8 changed (measured by the implementer, branch `agent/sonnet/P-ELITE-BENCH-1` @ 2a653ec59, seeds 1..80)
1. All 56 sampled minute-5 bot builds hold **0 cards**. Structural: cards come only from elite chests, so a player's first
   elite fight has none. A card floor in the oracle can never be met.
2. 39 of the 56 builds hold **0 stacks**; the rest hold 3 to 51. The bot sample is a bare fighter more often than not
   (measured here: the first 16 sample builds, which the quick run uses, are all empty, so `bot_sample` equals `banked_0`
   fight for fight).
3. So the bare-vs-build negative control cannot pass on the sample, and a table built on it measures "a bare fighter".
4. `fighter_sim()` under `live_content()` unchanged panics in `Sim::reset_active` (Source lifecycle, sim.rs:211); the
   bench needs `lifecycle: ArenaMode::Off` (the implementer's `config()` also turns regen and quests off: its own choice).

### The reference build: banked camps (workbook model)
`docs/quests/FUTURE_ONLY_Quest_Design_Discussion.xlsx`, sheet `Augment_Value`, assumption `banked` = 12 CE ("camps already
banked at pick-up") at t = 5 min; one camp = 12 stacks. For a seed `s` and a count `N`:
`banked_camp_build(probe, s, N)` draws N normal (non-elite) camps of the world (with replacement, seeded by `s`) and grants
12 stacks of the stat each drawn camp's normal kills pay (`probe.camp_buffs()[i]` under `CampBuffRule::Themed`, else the
camp's own `mob_type`; the stat mapping is `rh_sim::modifiers::farm::DEFINITION`). No cards, no boosts. It is applied at
tick 0 through `trusted_build::apply` (the Plant note of section 11 stands). Stacks of one stat merge into one entry, so
the stack total is exactly N x 12. In a run, the camp draw of cell seed `s` uses the probe world of seed `s`.

### Report shape
- Columns (constants in `elite_bench.rs`): `banked_0`, `banked_6`, `banked_12`, `banked_18`, `bot_sample`
  (`BANKED_CAMPS = [0, 6, 12, 18]`, `REFERENCE_CAMPS = 12`, `BOT_COLUMN`). `banked_0` is the bare fighter and replaces
  `--control-bare` (dropped; passing it is not required to work).
- Cell order: faction, weapon, elite kind, seed, then column (the 5 columns innermost, same fight seed and camp for each).
  A skipped cell is listed once, in `skipped`, with no column. Every cell has `column` and `camps` (N, or null for the
  bot sample) and `build_index` (null for banked columns; for `bot_sample` = ordinal of the (faction, weapon, kind, seed)
  place, skips included, `% builds.len()`).
- `per_camp[]` and `overall` keep `samples`, `deaths`, `death_rate` as the **reference column (banked_12)** and add
  `columns[]` (`column camps samples deaths death_rate ci95`), one entry per column in the order above. `ci95` is a 95%
  interval of the death rate (Wilson; `[lo, hi]`, null when `samples == 0`).
- Top level: `reference: "banked_12"`; `builds` describes the bot sample (`source`, `tick`, `count`).
- Table (stderr): the caveat, a header naming the five columns, one line per camp with its sample count and one `{:.1}%`
  per column, an `overall` line, a line that the reference is `banked_12` and that bots bank far fewer camps than the
  workbook player, and the owner target (10-20%).

## 11. Known traps
- **Feature isolation.** `elite_bench.rs` is `#[path]`-included by the bin under `cfg(feature = "elite-bench")` and by the test (where rh-headless's dev-dependency on rh-sim `trusted-status-probes` supplies the API). Never add it to `lib.rs`, never add `elite-bench` to `default`, never name it from `rh-server`. A self dev-dependency (`rh-headless = { path = ".", features = [...] }`) was tried and rejected: it changes `Cargo.lock`. `crates/rh-sim/tests/trusted_build_leak_paths.rs` also guards `default` lists, dotted dependency tables, the workspace root and `cargo tree -p rh-server` (offline, `--locked`: verified to run in this tree).
- **Plant Your Feet (coordinator, integration review).** `trusted_build::apply` leaves `card_still_since` at 0, so a holder granted the card just before a fight would plant its first swing at once (`cards/mod.rs:144`); the in-game chest grant behaves the same, so it is not a seam bug. Chosen design, pinned by the oracle: apply at tick 0 before the first step and let the fighter walk the approach (4-10 tiles); each moving tick resets the clock (`cards/mod.rs:167`), so the opening swing is not free. The report carries `build_applied_tick` (0), `start_dist` (128..=320) and `first_hit_tick` (>= 1). Do not apply later and do not touch `card_still_since`.
- **Minute-5 is survivors-biased and the matches end early.** Run on this tree (`source_soak`, map seed1, 6000 ticks): seeds 1-4 and 8 terminate at ticks 1495, 2241, 1260, 908 and 1762; seeds 5-7 reach 6000. So only about 3 in 8 matches reach minute 5, and a build is read from whoever is seated then. The file must say which seeds ended early, and the report states the sample size.
- **Bots misvalue the reworked cards until P-AUG-BOTS-1 (wave 7).** The minute-5 builds are what bots pick today, so the death-rate table before ELITE-TUNE-1 measures "today's bot builds" and may not be the build an owner-directed player would have. Say so in the README. With elite numbers equal to legacy until CONTENT packets fill the tables, the first table is a baseline, not a result.
- The Brawler swings from 80 u whatever the weapon: death rates are "Brawler with weapon W".
- A fight that kills the fighter must stop at once and report `died` (as `fight()` does); healing/damage tallies follow `fight()`.
- Do not use `HashMap` in `rh-headless` code that orders output; keep the cell order above.
