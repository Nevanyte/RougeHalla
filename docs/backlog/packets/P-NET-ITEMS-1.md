# P-NET-ITEMS-1 — Discover a weapon and pick it up from an observation

**Proposed integration packet.** A human joining a room and an external headless policy must both be able to find a visible container, order a pickup, see the result in both self slots, and recover the current item view after reconnect. Neither needs access to authoritative state, fixture numbering or a debug command. This packet covers the three container kinds actually implemented by P-COMBAT-1. It does not claim legacy loot generation, potions, reward choices or other mechanics are ported.

## What is public

`systems/items.rs` allocates global ascending container IDs and item UIDs; the authoritative replay setup and parity fixtures legitimately depend on those. A gap between IDs of *visible* props would expose another creation. Neither number, a victim actor ID, the world count, a contents array, the seeds, the private birth tick nor the internal vector offset belongs in a public item row. Keep `Sim::containers()` for privileged tooling. Use distinct Rust/C# types for `PickupHandle` and actor ID. Only an actor ID can appear in Hit/Death/Block or an actor snapshot. A pickup handle has meaning only to its issuing seat and only in Pickup/visible-prop records.

Build the following view in `rh-sim` from the same frozen tick as `Observation`. Share the exact directed radius and `MASK_SIGHT` point test with refusal filtering. Keep fighter-pair sight-cache keys separate from point targets. An absent viewer means no rows and no self inventory. Use current scene vision, including the corresponding viewer-status rules as P-VISION-1 lands; do not publish remembered props as current. Public cues follow `packages/client/src/render/{interact,ContainerView}.ts`, `RaidScene.ts` (`syncContainers`, pickup focus and HUD), and `packages/server/src/sim/loot.ts`:

| View element | Fields and disclosure rule |
| --- | --- |
| Own inventory | Active slot 0 or 1, and two optional carried weapon kinds. Empty slots have no weapon, even though the active attack falls back to fists. Preserve existing public active weapon on actors. Other seats never get this inventory. |
| Every currently visible prop | Pickup handle, public kind (chest/ground/body), position on the existing wire position grid. Compare and sort using the *published* point values, including in policy item views. A prop may be displayed before birth protection permits taking it. |
| Ground | Its visible weapon silhouette/type. |
| Chest | Open graphic when `opened || first_item_absent`, matching `ContainerView.update`. Never send its weapon type, second item, reward entitlement or seed. |
| Body | Public callsign label from the roster, as drawn by the old client. No death source, actor ID, slots, inventory size or carried item types at a distance. |
| Interact focus | At most one offered row, selected from visible, eligible props in reach using the authoritative position and `MASK_MOVE`. For a standing player, choose nearest, then canonical public row order on equal distance. A focused body can show its first weapon in the pickup hint. A focused chest says open chest even if it has a weapon. No first-weapon hint for the other reachable bodies. Compute in core; Unity and policies consume the same choice. The server checks again on execution. |

Use existing checked position encoding, slot/weapon codes and UTF-8 length conventions. Define the optional slot/weapon code as `0 = empty` and `1 + WeaponId::code()` for the five carried kinds (1 sword, 2 bow, 3 wand, 4 shield, 5 axe). Fists is never carried. Keep types distinct from the actor kit byte. Compute focus before final ordering, canonically from public kind/position/label and eligible reachable props; exact overlaps with equal base appearance represent equally eligible physical choices. The focused HUD hint is itself a permitted visible fact. Never use a private item UID, hidden second item or unopened content to order visibly distinct props.

## Exact target without a global identifier

Each human connection, policy seat and external headless observer owns one small private **item offer**. An offer is a batch of displayed rows and the private IDs to which their pickup handles refer. The seat allocates a consecutive block of checked nonzero u32 handles from 1, exclusively for rows it offers. Handles are immutable exact-target references. Public sorting is by quantized x/y, kind, label, appearance, focus and visible hint. Identical rows serialize identically apart from consecutive handles, so choosing a physical order for these ties does not change the bytes. A physical tie can use store iteration only *after* every published cue compares equal. Previously offered handles cannot be rebound to a replacement at the same position.

At the first actual observation, on a change to the ordered **public** rows (comparison excludes handles), or after 20 simulation ticks since the last nonempty offer when props are still visible, replace the whole offer. An empty set replaces a nonempty set immediately; a continuing empty set allocates nothing and never refreshes. The periodic refresh allows a visually identical replacement to receive a valid reference without leaking a hidden change via an off-schedule refresh. This rule only runs on complete observations offered to this seat, never intermediate catch-up steps, event-only collection, speculative encodes, calls polling the same tick, skipped policy decisions or while disconnected. `observe` must remain read-only on `Sim`; keep an explicit observer-owned projector in every public action-producing path, including the headless external API. Do not cache a shared viewer map in `Publisher`. A stand-alone convenience `observe` that creates a fresh disposable projector must be distinguished from a multi-step action-producing observer, or migrate that entry point to require the reusable projector.

Keep current bindings plus the private bindings retired within the last 20 ticks. Issue at most one distinct batch per seat per tick (a same-tick forced full resend reuses it). At 20 Hz this guarantees a full second of grace for an in-flight click **even across multiple intervening updates**. Retired batches need only first handle and an array of private IDs; at 512 rows the worst case is 20 × 512 u32 targets, allocated only as used. Measure the many-prop case. Never search raw world IDs as a fallback. Recheck current sight on use. If the original container has disappeared or become hidden, even a correct old handle receives the same owner-visible result as an unmapped handle. Other seats' numeric handles only ever resolve within the submitter's own offer. A valid handle references one physical target for its entire lifetime. A match/session does not wrap or reuse exhausted handle space; fail the offer explicitly. Bound wire rows and encoded bytes before allocation: start with `MAX_VISIBLE_PROPS = 512` and require a source bound for normal maps/loot placement. At live setup validate a conservative upper bound: existing persistent props + maximum possible bodies + available weapon units (each possible loose prop uses one weapon). Enforce this before accepting a map/rack loadout into a live room; the headless simulator can still run privileged large stress setups. Do not silently slice the scene or deliver a stale partial view. Validate UTF-8 lengths for body labels against existing bounded wire strings at setup/encoding.

Stage updates and commit only when the reliable ordered State was accepted for enqueue, or the observation was returned to its policy/external owner. This State must survive snapshot coalescing: enqueue as reliable under existing slow-client limits, in the same tick push (no extra wake). Close on reliable overflow, never advance published handle counters after a failed offer and then resume from the advanced values. On reconnect discard the old binding tables and preserve the seat's next unused handle; the room's existing connection generation fence must reject input from the old socket. A fresh process or restored external environment begins a new observer epoch, cancels old transport commands and returns a full fresh observation before accepting new offers. If an adapter claims to resume the *same* public input stream across restore, its private checkpoint must include its projector/counter along with the policy lifecycle. Sim-only checkpoints continue to contain only already-accepted private commands. Keep this distinction explicit in restore tests.

## Submission and replay

Resolve public Pickup at the common observer/input boundary (`rh-policy::drive_seats`, headless external intake and room human intake), before existing `validate`/`Sim::submit`. Split the public command representation from the private trusted resolved representation enough to prevent a public caller from naming a raw target. An unmapped nonzero handle still consumes exactly one normal action slot/budget and produces the ordinary owner refusal at action execution. Represent this as an explicit internal missing target, not a guessed ID or skipped submission. A zero public ID remains a malformed input per ADR 0012. Require standing/action gates, birth, continued sight, movement ray, range, two-slot rules, and ordering in the existing core handler. Preserve `Blocked` priority based only on the player's own condition. Keep trusted parity/replay inputs with private exact targets; recorder captures resolved private commands, including misses and budget refusals as required by the current replay semantics. Run replay through the same validate/queue/execute path without replaying socket publication or policy frame cadence. If the new private input form changes durable encoding, gate the format and keep current own-build replay/checkpoint validation explicit.

## Wire and presentation

Allocate this change once in the coordinated versioned State integration, with `OBSERVATION_VERSION` 3 → 4 and the strict wire version 5 → 6 unless another coordinated bump already owns the shared files. Do not extend a shipped v5 decoder silently, or bump separately for chest, body and each weapon. ADR 0011 reserves server tag `0x88`, reliable keyed state, and full State after Welcome. Keep v5 Pickup tag 7 and nonzero u32 little-endian payload; only the source/meaning of the number is public. Keys (proposed v6):

* `1 Inventory`: presence u8, then when present `active_slot:u8, slot0:u8, slot1:u8`. A present slot may be empty. Absence clears all self inventory.
* `2 Props`: `row_count:varint`, then each row `handle:varint, x:u16, y:u16, kind:u8` and kind payload. `Ground(1)` has weapon byte, `Chest(2)` has strict open bit, `Body(3)` has callsign string. Finish with `focus_handle:varint` (0 or a listed handle), and if nonzero one optional weapon code (only the focused body may carry it; ground already has its kind). Enforce strictly ascending nonzero handles, legal kind/weapon/flag combinations, no duplicates, count and frame bounds before allocation. Both keys are complete replacements, never append lists. Empty prop list clears the view, including focus. Missing key in an incremental frame retains that key's previous value.

After each Welcome send both keys, even empty. An active resync also sends full keyed State. Afterwards send inventory on change, props on change/public renewal. Apply frames in socket order; reject a malformed frame before mutating any client state. Do not compare State tick against the latest *snapshot* tick to discard a valid reliable change. Bind Unity presentation to session-owned keyed state and use a separate prop-view map; draw three shapes, focus/press F, own active slot and both contents. Browser probe and C# reader/writer vectors must understand actual v6, including bad keys, duplicate keys/handles, truncation, oversize, empty clear, resume, mismatch and unknown Reject. Avoid comparisons/loading whole private containers in Unity. Measure on realistic prop counts before optimizing full replacements.

## Noninterference argument and gates

Consider two executions with the same public observer history, sample schedule, and initial next handle. Vary arbitrary hidden insertions, deleted hidden props, all raw IDs, or concealed contents while keeping legitimate observed cues equal. By induction the selected public rows, offer trigger (including renewal), allocations, count, order, focus, State change/no-change and bytes are identical at every observation. Bound private references can differ but the public counter cannot depend on them. This covers a previously overlooked case: a private entity swapped for a lookalike *between* samples. Consulting raw-ID continuity for refresh would leak that replacement. Here both views stay byte-identical; the old handle still targets the original. If a player attempts a pickup, they can learn its legitimate present outcome, as in the game; an unknown/hidden target is identical to a missing target and never changes inventory. Legitimately different public gameplay outcomes end the equal-cue premise. Exact-overlap tie bindings remain private until a real interaction produces a permitted new cue. This is deterministic noninterference for the item projection, not a claim about physical server timing.

A small untracked model exercised 12,288 sample pairs with hidden insertions before/among tied public rows and independently changed raw IDs; all matched. A fixed replacement at tick 1 with the same face stayed bound to its original ID through tick 19 and renewed at tick 20 independently in both worlds. This checks the design model only. A reproducible example for the Rust tests follows (both viewers stand in the same spot and see the same chest):

| Tick | World A, private | World B, private | Visible props in both |
| --- | --- | --- | --- |
| 0 | Chest #1 | Hidden ground #1–4, same chest #5 | Handle 1, closed chest at the same point |
| 1 | Original chest remains | #5 disappears between samples; identical closed chest #9 replaces it | No State change; handle 1 still binds to #1/#5, respectively |
| 20 | Original chest remains | #9 remains | Both emit handle 2, same closed chest |
| 21 | Order handle 1 | Order handle 1 | In A it can take #1 during grace; in B it must never take #9. The intentional different result follows the player's exact action. |

Require the following implementation regressions:

1. Paired sims drive the same observation/action sequence with different hidden creation/count/order, unopened contents, hidden body inventory and lookalike raw replacement. Compare item observations and actual emitted State bytes, including timing, count, IDs, order and empty transitions. Include omitted viewer, sight edges, wall vs low fence, collocated identical props, multiple observers and repeated same-tick reads.
2. Legacy public cues: two self slots (including empty active fists), hidden opponent's inactive slot, unopened chest contents, body at distance, focused body first item vs second, other reachable body, blocked focus through a fence. A valid shown target goes through the existing contest/order, cannot cross a wall, cannot target a replacement, and cannot act on the birth tick. Stale/unknown/other-seat/malformed IDs preserve normal limits, queue and owner-only refusal behavior.
3. From the ordinary headless reset, seed a trusted rack and let a policy using only its returned observation take/swap; replay the recorded inputs and restore between submission and execution. Run the equivalent actual live-server connection round trip with a controlled server-side rack setup (e.g. test room setup using existing `seed_weapon_container`, never a client command), including two clients, resume, resync, loss of sight, reliable backpressure, and input generation fences. Verify a real Unity client consumes its observed focus and updates the slots. Distinguish this exercise from the game's eventual full legacy map-loot generator.
4. Cross-language golden and negative vectors; repeated empty/no-change frames cost zero incremental State bytes. Record changed/nonempty full State bytes and bandwidth with a realistic rack/drop workload, and steady-state core/headless allocations. Fail unsupported size explicitly and verify known arena budgets.

**First implementation boundary.** Land shared core item projection + observer offer and public-to-private submission on headless external/policy entry points, with paired-world privacy and replay/restore tests. Keep this packet open. Then wire the same projector into human room seats, complete State codecs, trackers, Unity presentation, actual socket pickup and reconnect gates above. Record shipping acceptance only after a nonprivileged live client successfully discovers and equips the observed weapon.
