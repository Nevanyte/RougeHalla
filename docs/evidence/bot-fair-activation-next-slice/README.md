## Boundary and version facts

The live policy input must remain a complete accepted public frame: `ItemObserver::prepare` and `DeliverySession::prepare/commit` produce `AcceptedFrame14`; the accepted receipt owns an opaque session and cannot be constructed by external callers (`crates/rh-policy/src/delivery/frame.rs:231-247,285-310,450-465`). At this backend cut `rh_protocol::PROTOCOL_VERSION` is 14 (`crates/rh-protocol/src/lib.rs:171-174`), native `OBSERVATION_VERSION` is 22 (`crates/rh-sim/src/observe.rs:20`), and `Frame14::from_reconstructed` explicitly requires both context protocol 14 and the crate protocol (`crates/rh-policy/src/delivery/frame.rs:285-294`). The independently inspected primary is protocol 16 and already changes that check to `context.protocol == rh_protocol::PROTOCOL_VERSION` only; the exact one-hunk delta is documented in the correction below. Thus the v16 accepted-frame protocol gate is already addressed on the primary cut, though the Rust type/accessor is still named `Frame14`. Its future B1–B19 indicator packet remains queued in `docs/prompts/UNITY_REWORK_STATE.md` and is not a backend accepted provider. Do not implement another protocol bump against the current v14 base or assume the queued packet has landed. Root must pick the exact union base and version numbers before any wire lease.

`Frame14` stores owner, owner combat, actors, collections, event and FX batches, tick, source time and phase. Its accepted fact methods preserve unavailable versus delivered-absent values. Static Welcome tables still need explicit seat/static setup binding; they are not frame fields or per-tick observation facts. The primary's protocol-16 check removes the hardcoded v14 rejection without otherwise widening the frame intake contract.

## Smallest coherent first backend packet

Recommend a narrowly scoped **owner credited-mob-kill accepted-fact packet** after Root pins the final protocol-union base. This is the cleanest missing owner fact with a defined native producer and no need to widen another actor's visibility:

1. Carry the exact run-local owner counter from the actual credited producer (`Player.credit.mob_kills`), keeping it distinct from `WireSelf.kills`, GV and `mob_stats`. Specify initialization, increment eligibility, resolved/training exclusions, and reset boundary from real source paths.
2. Add it to the owner-only observation/protocol projection and typed accepted-frame accessor, preserving required/optional group semantics. Bump `OBSERVATION_VERSION` and the final merged `PROTOCOL_VERSION`; update Rust, C# and JS codecs and final golden vectors only on the selected combined baseline.
3. Prove owner-only delivery, exact producer-to-accepted value at run start and after credited/uncredited/training/resolved cases, reset/new-session behavior, and a missing-field atomic refusal before Brain/Memory/RNG/path state changes. Then source-compare only the Strategy/hunt consumers whose branches depend on the counter. No source capture changes or expected values installed in native state.

This packet must not claim F0 complete. Keep `Held(None)` separately blocked pending an explicit privacy/entitlement or source-consumer decision; do not bundle a raw hidden target id into the progress field. The next packet after this should be a source-backed provider/equivalence matrix for the missing dynamic families (remote immunity and fighter/mob cues, minimap/time, NPC continuity, projectile/event history, dynamic Vision, and whole-room alive), deciding one bounded family at a time. The primary B1–B19 indicator packet is an independent UI/provider queue and must be merged/reviewed before deciding exact wire tags or reusing fields such as B7/B10/B13/B17.
