# Proposed minimal activation patch (NOT APPLIED)

**Proposal for Root. Nothing in this file or in [activation.proposed.diff](activation.proposed.diff) has been applied to the repository.** The refusing/poweroff userdata, the zero-IAM template, `security.guard`, the preparation tests and every `deployable:false` / `installed:false` flag remain byte-identical at the code commits (see [source-audit.json](source-audit.json)). Applying this patch is not a deployment. Root still has to clear the real-host gates in [REHEARSAL-PLAN.md](REHEARSAL-PLAN.md) and give separate authorization.

The diff was generated with `diff -ruN` against scratch copies of the base files. On a scratch tree with the patch applied, the preparation suite passes 14/14 and the installer suite passes 97/97 ([activation-patched-suites.txt](activation-patched-suites.txt)).

## What the patch changes (5 paths)

| Path | Change | Why it is needed |
|---|---|---|
| `tools/staging-full-runtime/rougehalla-postgres.service.in` | `-c config_file`/`hba_file` move from `/etc/rougehalla/` to `/etc/rougehalla-postgres/` | **Seam found:** the private-config contract (`root:rougehalla 0750`) and the existing secret generator's parent check (`mode & 0o027 == 0`) together stop the `postgres` user from traversing `/etc/rougehalla`, so the existing unit cannot read its config. The executor installs PG config as `root:postgres 0640` under `root:postgres 0750 /etc/rougehalla-postgres`, and it refuses the legacy unit. The test `test_existing_postgres_unit_config_path_is_refused_as_named_seam` shows this. Granting `postgres` membership in `rougehalla` would expose the runtime secret file, so the patch moves the config path instead. |
| NEW `tools/staging-full-runtime/installer/rougehalla-expiry-bootstrap.service` | The required guard unit from [the expiry evidence](../staging-expiry-executor/bootstrap-required.service.txt), with `ExecStart` pointing at `host_executor.py install …` (pinned `python3.12 -E -s`) and `Wants/After=network-online.target time-sync.target`, `WantedBy=multi-user.target` | The host executor must be the guard's **main PID**, because it runs the expiry executor in-process (same `MainPID`, cgroup and `TimeoutStartSec<=120s`). Wrapping the expiry executor in a child process would break `verify_guard`. The unit is enabled so that a reboot re-runs the guard; the executor then sees the existing marker, refuses, and requests poweroff, so writers are never revived. `-I` must not be used because it removes the installer directory from `sys.path` (see the interpreter-flags red/green logs). |
| `tools/staging-full-runtime/prepare.py` | Adds `IamInstanceProfile: Ref InstanceProfileName` and three base64 **nonsecret** input parameters. Replaces the refusing userdata with a short script: `trap 'systemctl poweroff' ERR`, require the image-pinned installer, write `plan/toolchain/boundary` JSON into root `0700` `/etc/rougehalla-bootstrap`, install, enable and `start --no-block` the guard unit | This is the only delivery channel for run inputs. It has no curl, wget, AWS call or secret, and any failure powers off. The CloudFormation parameter limit is 4096 bytes, and the toolchain receipt (~2.5 KiB before base64) must fit. |
| `tools/staging-full-runtime/test_preparation.py` | Two assertions change: userdata now contains the ERR-poweroff trap and no `curl/wget/aws /secret/password`; Host has exactly `IamInstanceProfile: Ref InstanceProfileName` | These consequential test edits keep the test intent ("no credentials or network fetch in userdata"). |
| `tools/staging-full-runtime/security.guard` | `IamInstanceProfile !exists` becomes `IamInstanceProfile.Ref == "InstanceProfileName"` | The instance profile is the separate exact-object role from `contract.role_template`. Root must still review PassRole and the attachment. |

The installer's own `foundation.py` keeps `installed:false/deployable:false`. `ACTIVATION-HOLD.json` in both renderers stays as is. The patch also leaves `contract.py`, `transfer.py`, `host_material.py`, `host_device.py` and `expiry_executor.py` unchanged.

## Preconditions the patch does not satisfy (Root-owned)

1. **Trusted installer and tool delivery.** The patch assumes a Root-built, pinned image that contains `/opt/rougehalla/installer/` (the reviewed modules, `host_executor.py`, `host_executor/layout.json`, the guard unit) and the pinned tool trees (`/opt/rougehalla/{aws,postgres,age}`) at the digests in the toolchain receipt. The `AmiId` parameter would then name that image. Nothing here builds it.
2. **Volume pre-initialization.** The executor never formats. Before first boot, Root must create the ext4 filesystem with the planned UUID and write `rougehalla-volume-owner.json` (`root:root 0600`, `{"format":"rh-retained-volume-owner/1","volume_id","uuid","run_id"}`) at the volume root. The volume must be mounted at `/srv/rougehalla-data` (`root`, mode `0755`) by the image's fstab or mount unit. The reviewed collector checks the mount but does not create it.
3. **Bundle build.** `public-bundle.tar` must contain exactly the members in `host_executor/layout.json` (rendered units with a numeric `RuntimeMaxSec`, the patched PG unit, configs, preparation scripts, `runtime-identity.json` with protocol, content hash and migration version) plus `web/**`. The manifest must be bound to the run and its object version pinned. The account chat's native-artifact work is the likely producer, and this lane does not duplicate it.
4. **DNS/TLS ordering.** The executor requires a publicly trusted TLS chain for `rougehalla.com` on loopback within the guard window. The practice DNS record must point at the host before boot, and ACME must succeed in time. Otherwise the host powers off (fail-safe).
5. **Instance profile and PassRole** from `contract.role_template`, plus the account, cost and IMDSv2 settings already listed in the foundation README.
