## How it builds on the reviewed interfaces

| Reviewed module | How the executor uses it |
|---|---|
| `expiry_executor` | `execute()` runs **in-process** as the first action, so the host executor is the guard's `MainPID`, inside the same cgroup and the same `TimeoutStartSec<=120s`. Wrapping it in a child process would break `MainPID` checks. Before **every** later step, `gate()` re-runs `verify_guard`, `verify_units(end)` and `no_shutdown_pending`, re-reads `run-deadline.json` bytes against `material(record)`, rechecks `foundation.check_deadline`, and requires that the step's reserve fits the guard's observed `TimeoutStartUSec` minus 10 s. Any error, expiry or cancellation (SIGTERM becomes `KeyboardInterrupt`) calls `expiry.shutdown()`, so no work gate is ever returned. The timer is never stopped, disabled or renewed. |
| `contract` | `validate()` on the plan; `strict_json`; `stamp`. `mode:restore` refuses, because remote-writer fencing has no interface (see seams). |
| `host_device` | `collect_and_validate()` runs **after** the exclusive `writers.lock` flock is held, and again before the marker. The held data-directory descriptor's `st_dev` must equal the validated `mounted_device`, and identity fields must not change between the two samples. `LinuxProbe.trusted_tool` guards every real subprocess. |
| `transfer` | `get_command()` is the exact download argv. `verify_download()` (length, SHA, version, content range) and `inspect_bundle()` run before any install write. `put_ciphertext_command()` / `verify_put_response()` handle the backup upload, whose receipt keeps `offhost_restore_proved:false`. |
| `host_material` | `pg_role_input()` is the only role SQL, sent to `psql -f -` on **stdin** after redaction and durability settings were observed. |
| Existing host scripts | The installed `init-runtime-secrets.py` generates secrets. The installed `run-runtime.py` is imported to prove Source's durable spool and that Training has none. `backup_archive.check_training_spool` checks the empty Training tree. `backup.sh` is the real producer. |

the kernel's own JSON listing is verified semantically, and the `rougehalla-egress-limit.service` that Caddy `Requires=` is installed → **volume fence**: held data dir, exact `rougehalla-volume-owner.json` (volume id, UUID, this run), no marker, no active owned unit, exclusive `writers.lock`, device revalidation + `st_dev` binding, foreign-entry scan, exact layout dirs on the same device, no pending bytes → download + verify → install (manifest equals layout; `web/**` names restricted; each member goes to a run-scoped temp `O_EXCL|O_NOFOLLOW` file, is hashed while written, fsynced, owned and moded, and published by create-only `link`; identical existing members are accepted on restart, anything else refuses; full readback) → unit and config binding (exact `User`, `ExecStart`, `ReadWritePaths`, marker condition, no indirect configuration or credential references, `RuntimeMaxSec + 180 s` must fit the deadline even if the service starts at the end of the guard window) → secrets (generator exactly once; `root:rougehalla 0640`; exact 64-hex shape; partial or odd secrets are never regenerated) → PostgreSQL (`initdb` as `postgres` only into an empty dir; temporary `pg_ctl` with **no TCP listener** and a private socket; observed `fsync/synchronous_commit/full_page_writes=on`, `log_statement=none`, `log_min_error_statement=panic`, `scram-sha-256` **before** the password goes over stdin; observed non-superuser login owner, `PUBLIC` revoked, no memberships, only two login roles, SCRAM verifier; stop) → marker (re-collected identical device, same lock inode; binds run, deadline, plan hash, artifact, volume, device snapshot, installed tree hash, runtime identity, receipts; `deployable:false`, `accepted:false`) → release fence → `daemon-reload`; units loaded from the expected fragment, no drop-ins, not enabled → ordered starts: postgres (service settings), source (readyz plus observed migration version, all tables app-owned, zero seeded profiles), training, egress guard, caddy (publicly trusted TLS for `rougehalla.com` on loopback; `/control` and `/training/api` 404; `/info` identity) → backup timer at `deadline − backup_seconds − 180 s` (start-only, never enabled) → cleanup of **only** this run's verified download.

`backup --run-id` (separate unit): stored inputs bound to the marker; deadline bytes and armed timer checked; existing `backup.sh`; quiescence observed; private owned ciphertext; exact conditional checksum PUT; receipt marked `independent_restore_required:true` and `offhost_restore_proved:false`. The ciphertext is kept.

## Seams found (precise)

1. **PostgreSQL config is unreadable under the existing contract.** `/etc/rougehalla` must be `root:rougehalla 0750` (private-config contract and `init-runtime-secrets.py`'s `& 0o027` check). `postgres` cannot traverse it, but `rougehalla-postgres.service.in` reads `/etc/rougehalla/postgresql.conf`. The executor installs PG config under `/etc/rougehalla-postgres` and refuses the legacy unit. The fix is in the proposal.
2. **Restore continuation:** no interface proves an older remote writer is fenced. `mode:restore` refuses before any work. Root's fencing proof has to become a verifiable input first.
3. **Volume pre-initialization and owner record:** the executor requires `rougehalla-volume-owner.json` (format defined here), but no reviewed component writes it. Root's pre-initialization runbook must, and the executor never formats.
4. **Installer and tool delivery:** the executor and pinned tool trees must already be on the host (a Root-pinned image). Userdata can deliver only the three small nonsecret inputs, within the 4096-byte CFN parameter limit.
5. **Startup budget:** the whole install runs inside the reviewed guard's `<=120 s` startup window, which `verify_guard` enforces. The executor refuses a step it cannot finish rather than being killed mid-step. Real timing, especially download size and ACME, is unmeasured.
6. **nft JSON shape:** reviewed from memory and fail-closed. It must be confirmed on a real kernel (rehearsal A4).
7. **No on-host observation channel:** with no SSH or SSM by design, real-host evidence is console output or public endpoints. `StandardOutput=journal+console` on the guard is an optional review change.
8. The `aws` CLI's default install puts a **symlink** at `bin/aws`. `trusted_tool` refuses symlinks, so the pinned layout must use a regular file. Runtime units exec `/usr/bin/python3` (a symlink), which is not hash-pinned.
