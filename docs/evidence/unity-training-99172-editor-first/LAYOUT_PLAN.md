# Training90 native layout plan (source review only)

This is a proposed capture route, not a test, screenshot, layout pass, or server-application proof. The frozen checklist is `docs/evidence/unity-training-integration/LAYOUT_CHECKS.md` at `e0da2de0b5100d979901aa5e20cc3d8f964e0626`. The current training gate must complete its single 90-case run and cleanup before any separate layout preview is authorized.

## Build a separate offline preview through the real ownership path

Do not call fixture methods, NUnit `SetUp`/`TearDown`, or rerun any of the 90 cases. The tests' nested `Fixture`, `FakeTransport`, and account doubles are private test code. A standalone editor-only preview can duplicate only the minimal transport behavior in its own harness, then drive the production flow:

1. Create a preview-owned `MatchClient`, `MatchHud`, Canvas, and dedicated `EventSystem`/`InputSystemUIInputModule` under a temporary preview scene/root. Snapshot the existing scene/root IDs, active scene, EventSystem/current selection/modules, Input System settings/device identities, focus, camera/render target, resolution and relevant PlayerPrefs first. `MatchHud.Initialize(client)` creates its own Screen Space Overlay Canvas (`MatchUI`) with a `CanvasScaler` configured to 1920×1080, Scale With Screen Size, match 0.5; it also uses or augments `EventSystem.current`. The helper must keep the original EventSystem untouched and restore its active/current state after the preview.
2. Supply a deterministic fake account transport/credential store and a local `ITransport` implementation, then call the ordinary public `MatchClient.Join("alice", faction, MatchLaunchMode.Training)`. The existing test seam injects `AccountOwner` and `_transportFactory` through reflection because those setters are private; if the preview uses that seam, pin the exact fields and scope it to this disposable root. Do not bypass launch validation by directly assigning `Session`, calling `TrainingConsoleView.SetLaunchContext`, or writing confirmation fields.
3. After the public join has created its real `Session`, open the fake transport and deliver encoded `ServerMsg.Welcome` and `ServerMsg.Snapshot` frames through its `Received` event. Use a fixed `MapBlob` and `Phase=1`, `Training=true`, populated `Me`; label the display as staged offline server facts. This exercises the actual decoder, accepted-snapshot confirmation and HUD subscriber path, but is not evidence of a real server or applied Train command.
4. Render the owned `ArenaView` from the delivered map/actor when needed for the checklist's center-character check. Do not use the existing `UiLayoutReview` helper as the Training-ready setup: it creates a direct `Session`, calls the internal `InitializeLayoutReview`, and lacks `_sessionTarget`, so `MatchClient.ConfirmedPractice` remains false and `RefreshTrainingConsole` correctly leaves the console unbound.

## Capture and interaction route

`MatchHud.Initialize` configures `MatchUI` as `RenderMode.ScreenSpaceOverlay`. A camera `RenderTexture` / URP `SingleCameraRequest` will therefore omit this overlay. Use a real Game view/backbuffer capture at the requested native dimensions for acceptance; alternatively, any camera-canvas conversion is a diagnostic-only adaptation and must be checked against the actual overlay bounds before treating it as equivalent. Hold the aspect ratio at 16:9 and record actual `Screen.width/height`, CanvasScaler scale factor, safe area, and viewport. If the Editor cannot provide exactly 1280×720 and 2560×1440, mark that case unavailable rather than relabeling a resized RT as native.

Capture all four combinations: 1280×720 and 2560×1440, each at text scale 1.0 and 1.5. `ShowcaseSettings.SetTextScale` publishes a `Changed` event which updates registered `MythicTextScale` controls; changing it also writes `roguehalla.showcase.textScale` and schedules a preference save. Record actual effective text scale and representative TMP font sizes, not just the requested slider value. The source checklist's console-root expected bounds are `(19.2,129.6)–(614.4,633.6)` at 1280×720 and `(38.4,259.2)–(1228.8,1267.2)` at 2560×1440; compare observed world corners and canvas factor.

For each combination inspect collapsed verified Training, expanded panel top, and panel bottom after scroll. Use actual `EventSystem.RaycastAll` / pointer interaction on the toggle, close and cycle/action controls, actual wheel/keyboard scrolling, and focused stack entry; capture the underlying raycast target and whether the expected control receives the event. Check the center actor, top-left stat overlap, Leave/header, lower-left health and minimap. Long labels and descriptions need visual raster inspection at 1.5 scale. Tests or hierarchy bounds alone do not establish hit targets, clipping, or legibility. The checklist's required behavior is broader than screenshots; record Escape, focus loss/regain, Tab, modal suppression and safe-input behavior as separate observed interactions, without inferring those from test results.

## Restoration and evidence limits

Keep all preview objects in the temporary root/scene and destroy only those owned objects in `finally`, including partially initialized Canvas, EventSystem, Arena, client and transport. Restore previous active scene, original EventSystem enabled/module/current-selection state, Input System settings object and flags/device/current keyboard, screen resolution/game-view settings, focus, camera target/`RenderTexture.active`, and every touched PlayerPrefs key including whether it was absent before the run. Restore absent keys by deleting them, not by writing a default. Wait for no preference autosave after restoring, or explicitly verify the disk-backed preference state. Verify original scene roots and source hashes before declaring cleanup complete.

The existing checklist's expanded console intentionally overlaps the top-left stat region; report that overlap rather than treating source anchor calculations as a visual pass. A decoded local Training snapshot can prove composition and event routing only. It cannot prove server acceptance/application, gameplay, browser behavior, accessibility acceptance, or performance. The native capture also does not replace the one-run 90-case gate.
