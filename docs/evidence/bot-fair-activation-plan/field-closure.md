# F0 source-to-accepted-field closure

**Status: planning review at integration source cut `6aaa4c6d33dad8a47ab7957b41d420fa78954af6`.** This is a
read-only classification of the admitted private TypeScript Brain's actual `Percept`/FrameRing consumers against
accepted protocol 14. It is not a wire proposal or implementation admission. The current integration tree is at
`9cc4e0ad7e8846ecafdffef8c328ab4e2a672072`; the gameplay source, protocol and Rust producers cited below are unchanged
there. No tests, captures, native runtime or builds were run for this review.

2026-11-10 documentation correction after independent review: the owner progression/lock gates, existing owner-combat
facts, actual MatchStart versus seat/static setup, mob ranged-cue consumer and delayed adapter throttle boundary are
classified explicitly below. This changes no source/protocol/implementation and does not release live binding.

“Available” means an entitled accepted field is already carried with enough provenance for an adapter to preserve it;
it does not say a full Percept composer exists. “Derivable predicate” is limited to a deterministic conversion from
accepted facts under an explicit producer invariant. “Needs provider” means current protocol 14 does not carry a fact
the source consumer reads. “Source-only/not live-required” means the source interface has a field, but current Brain
execution does not consume it for decisions/state; it must not be added to the public schema just because it exists.

## Identity and clock rules established by current producers

- **Players:** `Sim::add_player` increments `World.next_id` (`crates/rh-sim/src/sim.rs:381-382`). `PlayerRef` can preserve within-match identity only with the opaque delivery session/match fence and a supported no-overflow lifetime. Do not persist player IDs across matches.
- **NPCs:** presented NPC references are public-cue ordered, but `ActorRefs::stage` renews on each sampled tick (`crates/rh-sim/src/actor_refs.rs:220-239,277-289`). The old and new ids may refer to the same actor, or new ids may be assigned after an observed-scene change. Current protocol deliberately does not earn cross-sample identity.
- **Items:** `ItemObserver.next` assigns increasing handles, `reconnect` preserves that counter, and retired rows are grace-limited (`crates/rh-sim/src/item_view.rs:206-280,752-778`). Handles are viewer-issued actions scoped to their binding; they are not durable world object ids.
- **Time:** accepted `source_time` is a validated nonnegative finite server clock (`delivery/frame.rs:285-372`). Keep `tick`, accepted sample ordinal, source time, source delayed `viewT`, minimap refresh time and any per-event time distinct. No tick-period formula substitutes for an uncarried time.

## F0 closure decision and minimal next ownership

The existing protocol-14 consumer can support a fair full Brain only after an accepted-history composer is added, but
it does **not** yet close owner `mobKills`, source-equivalent held-but-redacted lock handling, remote immunity,
remote draw/windup, minimap dot history, stable NPC continuity, projectile courses/IDs, several event shapes/times,
and explicit static feature/content binding. These gaps require a source
consumer proof or narrowly entitled provider review before dispatch. Bow draw, wand cues and flight courses mentioned
in the unmerged Wave3 branch are not current accepted facts; that branch has unfinished decoder consumers and is not an
available producer.

Backend preparation that can proceed without a wire change: implement/test the pure typed composer over only currently
accepted fields; preserve `Fact` optionality and identities; implement source interpolation/teleport reset over actual
accepted history; prove the same-sample potion boolean invariant; use the already allocated function-level compatible
Memory/Strategy/Tactics/module cores; bind final map/features/content identifiers; and add hidden-state twin tests against
identical accepted frames. Keep missing facts as explicit refusal gates so no partial/default Percept reaches Brain.

Owner `mobKills` and target identity behind Held(None) remain explicit unresolved source-equivalence/provider gates;
this plan does not choose a history reconstruction, new field, hidden identity, or default. Held-ness itself is already
published. Close those exact source requirements before a live-binding dispatch; private declared-input Brain work is
independent. Event-time providers likewise remain conditional on whether a reviewed runtime/accepted-clock proof can
supply the exact consumed times; no generic tick-times-period shortcut is established.
