## Native assertions and implementation constraints

- The current `notices_source_tests.rs` constructs the captured seed/config and fixed map through `live_tests::arena`, binds player joins, submits actual input actions, compares ordered Toast/GV fields, and checks previews through `observe`. The current selected test executes only source indices 0 and 4. It can remain verbatim as required.
- Its `apply_action` accepts only `place`, `hp`, `weapon`, and `input`, and panics for other source action kinds. A continuation therefore needs explicit, strict handling for the frozen `noncanonicalSetup`, `expireSoon`, and `inlineProducer` actions. It must consume all action records in sequence and fail on unknown action, invalid/missing typed binding, wrong source definition, or ambiguous produced identity. Do not silently skip unsupported actions or cast an unverified source ID to an unrelated native object.
- The current preview helper is private to the existing test module. A sibling continuation module cannot call it directly. Keep the existing test untouched and implement the small independent assertion helper in the new module (or obtain a separate explicit allocation to share a parent helper). For every source `questReveal`, assert the entitled owner's actual QuestView row fields, absence of the hidden definition from the public source frame, and absence of that definition from every foreign human's QuestView regardless of row state. Use source reveal facts to select the viewer/definition for assertions only; never create reveal state from them.
- Compare the complete ordered Toast/GV vectors for each selected source case, including tick/time, kind, typed recipient/privacy, text, and GV actor/amount/reason. At each direct producer boundary, attach the actual current tick/time before mapping events; ordinary step notices use that step's tick/time. Report source/native total event counts and retained/excluded notice counts per case. Do not infer all-event parity from notice equality.
- For case 1, explicitly verify status/carrier diagnostic setup changes only the named actual offer and leaves its real produced box/item retained, then use actual pickup inputs and verify expected non-consumption. For case 2, preserve the exact ordinary action chronology so actual pickup progress, discovery, aggregate expiry, and completion order remain connected. For case 3, call the full producer and retain its original event-vector ordering. For case 5, use the existing actual mob hurt/payment producer path, preserve threat-derived credit, assert the exact nonempty before/after selected supply, and separate inline producer events from next-step events.
- Source `questReveal` events in cases 1, 2 and 5 coincide with recorded source ticks. When selecting a public source frame, bind it to the relevant captured boundary/action count rather than relying on an arbitrary same-tick frame if future corpus versions introduce duplicate snapshots.
- The packet's proposed only production-tree hunk is the private-to-`pub(crate)` visibility change on `systems::coliseum::teleport`, with no body, signature, call-site or schedule changes. It is technically adequate and scoped to the direct-producer witness. Root approval and the declared DeepSeek lease remain prerequisites; this review does not authorize that edit.
