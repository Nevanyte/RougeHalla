# Private SceneCandidate14 client transaction

This isolated component starts from the released socket prototype at
`800b6a5ffcb87cf8f4f5cb102d279e5fadf02b68`. It is opt-in source, not a change to the
normal Session, browser, Room, protocol14 decoder, or application publication path.
The coordinator owns integration and activation. The public integration branch is
not changed by this worktree.

The C# and JS leaves compose the existing Full-only `RHC14EXP` receiver with fresh,
private ordinary protocol14 decoder state. Original length-prefixed inner records
are decoded through the existing trackers. The complete eleven-family State is
validated before an opaque candidate is exposed. No live decoder is cloned or
temporarily mutated. Candidates retain the existing immutable byte view; copy-outs
decode into detached DTO graphs.

There is one pending candidate per serialized caller context. A complete decoded
candidate does not replace the applied-data pointer. `CommitApplied` is an explicit
trusted caller assertion that application acceptance has completed. It checks the
owning instance, local generation and exact pending candidate, then replaces the
component's applied-data pointer. It neither calls application code nor attests to
rendering, delivery, policy acceptance or a socket write. An explicit second call
serializes the exact existing 34-byte ACK from the current committed receipt.
No network ACK is sent automatically.

Malformed wire transactions close their own receiver while retaining previously
applied data. A wrong local generation, foreign candidate, superseded receipt or
closed context cannot publish or serialize a fresh ACK. A stale callback must keep
its captured owning instance; fencing bytes already handed to a future transport
is a separate integration responsibility. Application refusal closes the context
without replacing old applied data. ACK failure after application does not undo
the newly applied data.

Caller-supplied finite limits keep their existing meanings. In particular,
`retainedBodyBytes` remains the cumulative accepted encoded-body allocation budget
per epoch. It is not a bound on process RSS, detached DTO graphs, temporary copy-outs,
transport buffers, caller history or multiple contexts. No producer capacity or
product defaults are inferred from these small test profiles.

The new private fixture is generated by Rust's existing typed codecs, assembler,
receiver and ACK encoder. Its positive cue tail is explicitly synthetic: two
duplicate existing Fx batches keep their original tick and four occurrences.
Negative transactions are actually rejected by the Rust receiver after a valid
first scene, with its prior view preserved. This is not a legacy recapture or a
new gameplay producer.

Validation is pending. The source cut, original first failures, exact commands,
results and protected-file checks will be recorded before release. There is no
browser, Unity Editor, real client socket, default endpoint, server activation,
cloud, resume, Delta, resync or complete history acceptance claim.
