# Private quest bridge, protocol 14

Base: `6db02195abab67d9867f6340cc61a8dc7d4f6114`. This is a component transport contract, not admission of full hosted quests or giver actors. Existing outer tags and protocol-14 header remain unchanged.

State replacement key **10** is `Quests`; maximum State keys becomes 10. Omitted key retains the prior value. Its payload begins with strict u8 availability 0/1: 0 is unavailable/disabled, 1 is a valid view (including empty). All integers below are canonical unsigned varints unless explicitly specified; strings use the existing u8 UTF-8 byte-length prefix. Floating values are little-endian binary64.

Available view, in order:

1. unknown_count, display_unknown_count; owner_roster (0 absent, otherwise nonzero quest-only RosterId).
2. roster count, then each roster entry: nonzero RosterId, label string.
3. row count, then each row: nonzero QuestHandle, def string, giver.x f64, giver.y f64, status u8 (0 Preview, 1 Open, 2 Done, 3 Expired), expires_at f64, participant count; each participant is nonzero RosterId, accepted strict u8 bool, progress varint, visited u8; then carrier (0 absent/nonzero RosterId), done_by presence strict u8 bool and optional label string, flags u8 (bit0 can_accept, bit1 owner_accepted, bit2 owner_completed, bit3 owner_ready; high bits zero), owner_progress varint, owner_visited u8.
4. objective count; each objective is nonzero QuestHandle, at.x f64, at.y f64. These are navigation facts, never pickup or actor capabilities.

Bounds derive from the supported native publication profile: 20 offers (`QUEST_COUNT`), 8 seats (`MAX_PLAYERS`), 8 maximum collect placements per offer, hence at most 160 objectives and at most 8 per quest. These are publication limits, not a claim that every restored/synthetic state satisfies them; unsupported views refuse encoding without tightening restore or truncating facts. At most 8 roster entries and participants per row; labels/done_by at most 255 UTF-8 bytes (native checked_label), def nonempty and at most 16 UTF-8 bytes (longest current catalog ID). Unknown counts are at most 20 and display_unknown_count <= unknown_count. Progress uses the native u32 domain without gameplay thresholds. Visited masks permit only five faction-region bits (0x1f). Every position must be finite and within 0..=8191.875; deadlines finite and >=0 (including zero). A present view payload is bounded to 16 KiB, conservatively rounding up the complete worst-case bounded shape (under 14 KiB). Refuse overflow; never truncate. IDs use the entire nonzero-u32 domain; renewal can exceed the collection count limits.

Roster IDs and row handles must be unique within their own namespaces. owner_roster, participant IDs, and carrier must resolve to this view's roster; each objective must resolve to this view's rows. Duplicate display labels are allowed. Row ordering is native presentation order, not a numeric handle order. Do not derive owner_completed from done_by or a label match. Bool/status/mask domains are closed; no client-side gameplay evaluator is introduced.

Prop discriminator **7** is QuestItem. Following the existing generic prop position, its payload is nonzero QuestHandle varint and strict u8 fetch bool (0 token, 1 parcel). Its existing PickupHandle stays the only pickup capability. Native admission currently supplies only eligible, visible, in-reach pickup cues, not every source quest-item visual at general viewing range. Accepted quest navigation objectives are intentionally broader; this packet does not claim complete source visual parity. QuestHandle, RosterId, PickupHandle, reward and actor namespaces remain separate even when numbers coincide. The reconstructed props + quest view must have every QuestItem quest handle resolve to a row in the available view. Validate after candidate reconstruction (retained plus replacement collections) and before any state, seen-mask or tick mutation. A malformed frame applies nothing.

Input subcommand **17** is QuestAccept followed by nonzero QuestHandle varint. Subcommands 1..16 remain unchanged. It projects to native PublicCommand::QuestAccept, ItemObserver::resolve, validate, Sim::submit; preview, hidden, closed, stale or foreign refs never bypass native authorization.

Server publication stages quest view, props and native quest/item reference changes together. Encode/capacity/enqueue failure commits neither references nor collection baselines. Reconnect/resync must revoke old capabilities and deliver replacements. Full quest hosting remains gated pending the separately owned neutral giver actor slice. Protocol14 final composition, golden admission and provenance pins belong to the coordinator.
