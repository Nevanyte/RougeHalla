# Neutral giver and pooled presenter audit

## Source identity and scope

Audited the c6a55 source snapshot in the art checkout. The `evidence/as-tested-source.json` ledger identifies source `c6a55d3d68d0023e60ace98b55fd23f581217b38`; the current file hashes match that ledger for `SpriteActorPresenter.cs`, `ShowcaseActorLook.cs`, `ShowcaseIdentityOwner.cs`, `ArenaView.cs`, `SnapshotBuffer.cs`, `ShowcaseIdentityAssets.cs`, `ShowcaseSoundscape.cs`, `SpriteActorBarrierEditModeTests.cs`, `SpriteActorSignatureEditModeTests.cs`, and `ArenaPresentationEditModeTests.cs`. This is a source and test review only. No Unity runtime, Play session, build, or source edit was used.

## Findings

A valid quest giver reaches presentation with `ActorKind.QuestGiver`, and nullable faction, weapon, and mob type. The Rust observer test `neutral_giver_native_view_carries_no_invented_faction_or_weapon` fixes the source values as neutral faction, no weapon, and no mob type. The Unity protocol test `QuestGiverFullActorUsesKitSentinelAndOnlyOwnedRemoteViewMakesItNullable` checks wire sentinels `Faction=15` and `Weapon=15`; `SnapshotBuffer.Emit` makes them nullable specifically when `Kind` is QuestGiver. `ArenaView.PresentLatestNpcs` passes those typed observations into the presenter.

For that decoded fact tuple, the view is neutral and does not take a fighter catalog fallback:

- `ShowcaseActorLook.AppearanceKey(QuestGiver, ...)` returns null. `SpriteActorPresenter` explicitly avoids catalog fallback for givers.
- `Authored character` uses the generic neutral silhouette from `GetFactionSilhouette(-1)`, tinted `ShowcasePalette.MutedText`. Its fallback local scale is `(0.8, 1.35, 1)` and local position is `(0, 0.55, 0)`. The parent actor root scale remains `(1.2, 1.2, 1)` and is positioned by `ArenaView.WorldPoint(x, y)`.
- `Faction footprint` uses the unknown/neutral diamond, tinted muted; `Faction insignia` uses the neutral rune, not a faction-specific sigil. `ShowcaseIdentityOwner` hides its mantle, faction badge, mob role badge, and elite badge for a QuestGiver. The presenter's `StandaloneFactionBadge` is false.
- A null faction yields muted tint; a null weapon clears `AttackUntil`, clears the weapon sprite, and disables `Equipped weapon cue`. `TrySoundContext` requires both a weapon and faction, so it returns false for the valid giver. The `ShowcaseSoundscape` hit, block, and death paths require that context and skip these cues. Swing playback is keyed by the server FX weapon and only checks actor observation, so do not claim `TrySoundContext` suppresses malformed or unexpected Swing FX.
- The public observer contract gives givers `barrier_frac=0` and ring step `0`; the corresponding protocol fixture uses the zero defaults. Presentation therefore hides `Confirmed barrier` and all eight `Barrier ring step N` renderers for the valid delivered giver. Do not relax the fighter's delivered barrier/ring tests: those assert real nonzero shares and 0..8 ring segments.

The public eviction/pool path is internally consistent for fighter-to-giver and giver-to-fighter **after actual eviction**. `Begin`/`End` evicts an omitted actor; `Retain(emptyMembership)` also evicts it. `Evict` hides the root and calls `Identity.Clear`. When a pooled root is assigned a new actor, `Present` clears movement, attack, hit, and block expiry deadlines, resets dead state, and overwrites kind/faction/weapon. The same call recomputes neutral or fighter body sprite, body scale and local position, tint, rune, footprint, health, barrier/ring, status and signature cues, weapon visibility/sprite, light visibility, and identity overlays. The scale is assigned once in `Create`; reuse does not multiply it. `TryPosition` and the root transform expose the world anchor without inspecting private presenter state.

## Concrete issue to keep visible

An in-place change of `ActorKind` under the same still-active actor ID is a different path from eviction/reuse. In `Present`, a null weapon sets `AttackUntil = 0`, but `MovingUntil`, `HitUntil`, and `BlockUntil` are not cleared merely because the kind/appearance changes. The neutral body cannot display those catalog clips while `Appearance` is null; if the same active ID changes back to a fighter before those deadlines expire, an old walk, hit, or block clip can be selected. The current pooled-new-actor path resets those deadlines, so the requested eviction/reuse assertions should pass. Add a distinct same-ID kind-transition assertion if that transition is supported; otherwise record the contract that kind identity changes arrive as a new observation handle/eviction.

`AttackAt`, `HitAt`, `BlockAt`, and `DeadAt` are not zeroed on pooled reuse, but their corresponding action deadlines are zeroed. The next confirmed cue overwrites its own timestamp, and a new dead actor receives a fresh `DeadAt` after `Present` resets `Dead=false`. The retained timestamps alone do not select an old animation. Existing timer-reset tests use reflection; the public-scene checks below avoid that dependency.

## Recommended public Unity scene assertions

Use a fresh, identity-scaled parent `GameObject` and `new SpriteActorPresenter(parent.transform, Resources.Load<ShowcaseCatalog>("Showcase/Catalog"))`. Drive it only with public methods, using `Begin` -> `Present` -> `End` for each observed set. Search the hierarchy with `Transform.Find` / `GetComponent<SpriteRenderer>`; assert public API results from `Contains`, `IsLiving`, `TryPosition`, and `TrySoundContext`.

1. **Valid giver:** present an alive QuestGiver with `faction=null`, `weapon=null`, `mob=null`, `effects=0`, `signature=0`, `barrierPct=0`, and `barrierRingStep=0`. Assert `AppearanceKey` is null; root local scale is `(1.2,1.2,1)`; root world position equals `ArenaView.WorldPoint(x,y)`; `TryPosition` matches it; body sprite is exactly `ShowcaseIdentityAssets.GetFactionSilhouette(-1)` with muted tint and expected fallback transform; footprint is `FactionIndicators.GetFootprint(-1)`; main insignia is the generic rune with muted tint; weapon sprite is null and disabled; all `ShowcaseIdentityOwner` badge/mantle renderers are disabled; health is visible; barrier and all ring segments are hidden; `TrySoundContext` returns false.
2. **Fighter -> eviction -> giver reuse:** present an alive sword fighter with nonzero barrier and ring step 8, send `ConfirmedCue(id, FxKind.Swing)`, then omit it via `End` or `Retain(emptyMembership)`. Present a different giver ID and assert the same `Observed actor` root is reused, the neutral assertions above hold, and there is no weapon or barrier/ring residue. The test verifies visible state and sound-context behavior; it does not inspect private timer fields.
3. **Giver -> eviction -> fighter reuse:** evict that giver, then present a different alive player ID with a faction, sword, and zero barrier. Assert root reuse, faction appearance/mark and tint, visible sword, `TrySoundContext == true` with the delivered context, and hidden barrier/ring for zero delivered values. Follow with a fighter presentation carrying nonzero barrier and successive ring steps to retain the existing barrier expectation.
4. **Control:** retain the reused root's local scale and root anchor after each sequence. Check visible `SpriteRenderer.enabled`, `sprite`, `color`, local transform, and active GameObject state only; do not use reflection or claim wire/network/AI proof from this local presenter test.

There is no Unity presentation test for QuestGiver in this source set. Existing `SpriteActorBarrierEditModeTests` cover barrier eviction/pooling; `SpriteActorSignatureEditModeTests` cover signature cue eviction/pooling; `ArenaPresentationEditModeTests` cover observed actor removal and renewed NPC handles; the net test covers giver sentinels and nullable projection. The proposed assertions join those current coverage areas without changing them.

## Expected outputs for the coordinator's public sequence

For an alive QuestGiver with nullable faction/weapon/mob and synthetic delivered `barrierPct=35`, `barrierRingStep=4`, and nonzero signature bits, expected visible values are intentionally based on the supplied values:

- `Authored character.sprite` is `ShowcaseIdentityAssets.GetFactionSilhouette(-1)`; `Faction footprint.sprite` is `FactionIndicators.GetFootprint(-1)` (unknown neutral diamond); `Faction insignia.sprite` is `ShowcaseSprites.Get("rune")`. Body/footprint/rune colors are `ShowcasePalette.MutedText`.
- `Equipped weapon cue` has `sprite == null` and is disabled; public `TrySoundContext` is false.
- The synthetic `35/4` barrier inputs produce a visible barrier renderer and exactly four enabled ring steps. The presenter accepts those values for the neutral giver. This is not the native authoritative giver fixture: Rust `mob_view` explicitly writes barrier 0 and ring 0, so use zero when asserting the real giver's no-barrier state. Do not turn the synthetic nonzero input into an expectation that these delivered renderer values are suppressed.
- Signature icons are separately delivered bits. Known bits 1/2/4/8/64 map to `sigil3` / `spark` / `sigil2` / `weapon0` / `sigil4`; unknown bits produce the muted unknown rune. They can remain visible for the synthetic giver input and are not faction/role/elite badges. The authoritative giver fixture does not currently establish nonzero signature behavior.
- Faction, role, elite and mantle renderers owned by `ShowcaseIdentityOwner` remain disabled. Distinguish these identity layers from the main generic rune, footprint, barrier, and delivered signature row.

After empty membership evicts the giver and a new alive Fire player with a sword is presented, the reused root should show the `hero` appearance and faction identity, enable `Equipped weapon cue`, and pass `TrySoundContext` with the supplied fighter facts. With no new swing cue and no movement, the body's sprite should belong to that appearance's `Idle` frames and not its nonempty `Attack` frames; the selected hero asset has distinct source frame references for these clips. With zero delivered barrier/ring, both remain hidden. A subsequent fighter presentation with barrier and ring values must still show those exact values as existing barrier tests require.
