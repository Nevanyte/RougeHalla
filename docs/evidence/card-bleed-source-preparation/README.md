# Card bleed source preparation

Current follow-up: attempts1–4 are retained. Attempt4 reaches actual card and Fire signature damage but fails an overly restrictive classification guard; its full trace is unadmitted. The corrected guard is not rerun, no canonical source corpus exists, and mutation/bytecheck/review gates remain open. See [ATTEMPT-4](ATTEMPT-4.md). The preparation-only description below is historical.

This is an **unrun source-capture harness draft** for P-CARD-BLEED-FEEDBACK-1, prepared on base `4151b3af`. No source
capture, Docker run, build, or test was performed in this preparation task. It does not create or install
`parity/card-bleed/source.json`; source parity remains unproved until the capture and independent review complete.

The harness builds ordinary legacy `World`s with the existing core Card Runtime (and a full-profile mixed-source control),
adds players through `addPlayer`, enters the raid with a normal fixed 50 ms `step`, grants declared Hemorrhage cards using
the source chest grant, and queues every attack/release through `enqueueClientMessage`. It records each step's actual
`combat.landed` rows and emitted events. The capture asserts that its named controls reach real card DoT contributions,
the source 500 ms feedback boundary, a natural `settle`/`runEnded` before that boundary, ordinary teleport, a partial-report
raid reset, a non-card DoT, and a no-card control. Captured `cardFx` is only a convenience view over the recorded source
events, selected by the source card report's existing `hit`/null-weapon/no-signature/no-ability shape.

The legacy raw `FxChannel` aggregate has no historical viewer audiences. This corpus is intended to preserve that raw
source behavior; it does not claim ADR0013 contribution-tick privacy, native viewer entitlement, or public-wire parity.
No expected pending report or expected amount/order is supplied to the source runner, and it does not import or call
`flushBleeds`. Output bytes and source/harness input hashes are generated by the pinned source run. The source capture
checks are semantic reachability guards, not an independent oracle for Rust behavior.

## Exact next command

```sh

```

That writes a fresh corpus under a temporary directory and prints its path. After independent review chooses/adopts the
corpus location, set `RH_CARD_BLEED_DIRECTORY` to that location for the read-only byte comparison:

```sh
RH_CARD_BLEED_DIRECTORY=/absolute/path/to/card-bleed-output bash tools/card-bleed-fixtures/capture.sh --check
```

The default check target is `parity/card-bleed`, intentionally not created here. The Docker pattern pins Node.js
22.23.4/Linux amd64 and its image digest, runs `npm ci` inside a disposable container, mounts source read-only, and only
writes capture output to its dedicated output mount. This task did not check the digest/runtime compatibility or execute
the script.

## Review items before capture admission

- Confirm that the seven closed cases reach their asserted source events under the pinned runner. In particular, the
  exact timing of the first Hemorrhage tick, Fire signature DoT, early natural run end, and patience-triggered teleport
  are deliberately guarded by source-derived assertions but remain unobserved until execution.
- `startRaid` is called through the actual exported source producer after the initial ordinary partial report. This is a
  lifecycle-only reset control because a single normal match does not start a second raid; it is not represented as an
  ordinary 50 ms gameplay action. Review whether this is sufficient evidence for the `raidStarted` reset edge.
- Setup directly sets position, weapon, or HP only at declared bootstrap/boundary points. Damage and status creation are
  not seeded; attacks are queued. Review whether the early run-end setup at `p1.hp=0.01` falls within accepted diagnostic
  setup conventions, then confirm the final bleed tick kills through ordinary damage and settle.
- The pair-order scenario uses two source actors and two opposing targets so actual status ticks can interleave. The
  captured landed/event tape must be reviewed for distinct and repeated `(victim, source)` pairs before trusting its
  insertion-order coverage.
- The `full` profile mixed-source case must actually land a signature or ability DoT alongside a card DoT; if the guard
  fails, redesign the producer input rather than weakening it or fabricating landed rows.
- This first draft has no semantic mutation runner yet. Before freezing the corpus, add independent grouping/threshold/
  run-end mutation controls in the authorized new tool subtree, then perform repeated `--check` captures and source review.
