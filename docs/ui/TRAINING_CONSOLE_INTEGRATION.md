# Training console integration proposal

The reusable view is not wired into the shared HUD in this leaf. `TRAINING_CONSOLE_INTEGRATION_PROPOSAL.patch` is an unapplied proposal against public revision `3126e5c3`. Root must reconcile it with the settlement owner's changes before applying. It creates no Canvas, EventSystem, transport, protocol or backend rule.

The proposed hooks create the component under the existing MatchUI Canvas, bind/unbind it with the same Session, and pass `MatchClient.ConfirmedPractice` only when the client and HUD reference that exact Session. The view additionally checks the accepted Training fact and TimelineEpoch. Do not use the HUD's null-client/default confirmation fallback for this console. Welcome, accepted source-clock cuts, disconnect, rebind, disable and destruction revoke actions; a new owner confirmation is required.

The proposal keeps the existing TMP typing guard and also lets a focused console control own keyboard input. The decorated backdrop is click-through; only the scroll viewport and controls receive pointer hits. Opening preserves keyboard focus, pointer activation releases it, and keyboard scrolling uses the existing KeyboardScrollPane. Use Panel/Root for focus cycling only while the console owns focus. Do not globally steal Tab from the tactical map. Root must verify entry into the console by keyboard together with the existing HUD and tactical-map hold-Tab paths in the later native batch.

`HandleEscape()` closes/releases focus only while open and returns whether it handled that press. The proposal records a per-frame consumed flag so closing does not reclassify the same frame as game input. Closed consoles return false and never call Leave. This leaf does not implement or claim a global Training Escape-to-Leave path; the owner must preserve its own leave routing without a second invocation. Higher-priority panels keep Escape. Modal/window-loss integration should close or revoke the console in that same coherent batch.

Each action queues one existing Train command and immediately calls ordinary `Session.FlushInput`. This flush sends ALL current queued commands in their existing order and 16-command batches; it is not a selective Train transport. This explicit timing choice differs from waiting for the usual end-of-frame flush, and does not poll or advance the session again. Counts are server intents, not applied counts. Zero and elite stat requests remain subject to ordinary legacy/native admission refusal. No new eligibility filter or native widening is supplied.

Runtime proof remains required after integration: actual decoded Training join and matching mode confirmation; all five commands including chosen/random chest; reconnect, new Welcome and source-clock cut; stale callback/focus/teardown checks; wheel/keyboard/pointer behavior; no clipping at 1280 × 720 and 2560 × 1440 with text scaling; and no gameplay input while typing. The new Editor tests compile but have not executed. The prior 42 fixtures remain byte-identical; their older 42/42 engine receipt is not a native pass for this new component.
