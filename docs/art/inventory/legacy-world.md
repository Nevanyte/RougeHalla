# Legacy world, actor, combat and VFX inventory

Scope: the original Phaser world presentation only. It inventories world geometry, actors, map dressing, selection and combat feedback. The overall asset inventory is broader and also needs the UI/audio/static owners' lists. This document does not claim game-wide inventory completion.

## What the legacy actually contains

The original client has no authored raster images, audio, or font files according to [legacy inventory §8](../../legacy/INVENTORY.md). The world art is generated at runtime from Phaser `Graphics`, text, generated/baked textures, and data tables. Examples include fighter and weapon geometry, faction badges, hit/cast particles, map feature and prop art, and selection/route rings. There are dynamic visual records for map features/props, camps and mob types, quests, containers, traders, corpses, active fields, projectiles, statuses and one-shot combat FX. See the source references in each row below. A catalog entry or generator recipe is not a separate authored image asset.

The source snapshot is `70579162ce41a1325aaed1a65a34b65b779ad1e7`. The companion JSON records the Unity readiness-contract entry per counterpart separately from a runtime presentation assessment. Readiness status is not rendered implementation evidence; in particular older `presentation-inventory.json` entries can lag accepted protocol-13 evidence. Current runtime evidence includes the frozen browser proof for five factions, all five Wishes, and the real Trophy selection. Unity uses Flare artwork and procedural fallback assets; the legacy art being procedural does not imply Unity is complete.

## Source module index and audit boundary

The companion JSON indexes all TypeScript modules under `packages/client/src/render/`, plus `RaidScene.ts`, `HubScene.ts`, `hubArt.ts` and `hubLayout.ts` (59 total records (55 render modules plus four scene/hub modules)). Direct visual owners, generated art sources and support helpers are tagged separately. `RaidScene.ts` wires dynamic presentation; `HubScene.ts`/`hubArt.ts` add the walkable client-only hub dressing. Projection, culling, timing, interaction or pose helpers were checked for visible-family links but do not imply separate asset families. This census does not include `packages/client/src/ui/`, audio, HTML/CSS or all static files; those domains have separate inventory owners.

## Counts, boundaries and review notes

- 16 world/actor/combat family rows (including walkable hub dressing); 16 groups in the companion JSON. These are functional families, not counts of individual textures or all game assets.
- Catalog scope includes five factions, 30 named mob types (six per faction), five mob roles, six weapon ids (five item weapons plus fists), five Wishes, 14 status kinds and 34 named map prop kinds. Counts should be refreshed from their canonical tables if source changes.
- Map features, concrete map props, mobs-in-camps, quest locations and active FX are dynamic constructs. Catalog membership is enumerated here; a particular seeded map or match instance needs manual review against generated facts.
- All current cosmetic names and silhouette bits are listed in this inventory; refresh from `COSMETICS` when the table changes.
- Runtime assets are procedural in the legacy. Distinguish this from Unity's prepared Flare assets and staged preview: a staged lineup is not live server-fed evidence.

## Essential cue preservation

Keep identity, state, selection, danger and interaction legible through shape, placement, outline, label/icon and animation together; color may reinforce a cue but cannot carry it alone. Low detail may drop decorative noise and particle density, not actor identity, weapon shape, status state, target rings, projectile paths, windups or hazard boundaries. Reduced motion can stop decorative rotation/swirl and lessen camera/flash motion; it must retain persistent windup/cast warnings, hit/block/stagger/death confirmation and terrain danger. Hidden actors must not leak through their attached effects.
