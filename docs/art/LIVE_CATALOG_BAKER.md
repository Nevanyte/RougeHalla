# Showcase live catalog baker

`Roguehalla.Editor.ShowcaseLiveCatalogBaker.Bake(originalSource, expansion)` merges `ShowcaseCatalog.Actors` and `AssetReadinessCatalog.Actors` by exact `Appearance.Key`, with expansion entries replacing a same-key base row and expansion-only rows appended. Current inputs are expected to contain the original five rows and seven expansion rows. Duplicate keys within either input, null appearance rows, missing PNGs, non-integral sprite rectangles, out-of-bounds pivots, and fully transparent source frames are hard errors. Empty clip arrays are retained as empty; null clip arrays are normalized to empty. It does not read or merge the expansion environment sprites.

The output is a separate `ShowcaseCatalog` at `Assets/Art/Derived/ShowcaseLive/Catalog.asset`, outside `Resources`. Its non-actor fields (props, audio clips, and mixer references) are copied from `originalSource`. No input asset, PNG, source `.meta`, or importer setting is changed. The helper also writes `Assets/Art/Derived/ShowcaseLive/receipt.json`.

## Pixel treatment and packing

For every supplied frame in the eight catalog clips (Idle, Walk, Attack, Block, Hit, Death, Cast, Shoot), the baker reads the original PNG bytes directly into a temporary RGBA texture. It scans only the Sprite's source rect for nonzero alpha, unions that bound with the exact source pivot and one-pixel pivot clearance, then expands by two transparent pixels on each side where the authored rect permits. Pixels are copied byte-for-byte; there is no resize, rotation, color transformation, or frame reordering. The original PPU and FPS values, WorldHeight, GroundPivot, and all clip ordering are copied. The new sprite pivot is the old pixel pivot minus its trim offset, normalized by the new rect dimensions, retaining the same grounded pixel location.

Each appearance has its own non-rotated atlas. Shelf order is descending outer height, then descending width, then clip name and frame index. Items have four-pixel gutters. Packing starts at 2048 pixels wide and doubles to 4096/8192 only when needed; the packed height is rounded up to four pixels. An item or packed height that cannot fit below 8192 is an error. Atlas PNGs use a content-addressed directory under `Assets/Art/Derived/ShowcaseLive/Atlases/`; imported texture type is Default RGBA, sRGB, input alpha, no mipmaps, NPOT None, clamp, and CompressedHQ at quality 100.

The receipt records source PNG SHA-256 hashes, packed PNG hashes, per-appearance atlas dimensions and area totals, per-clip frame counts, and each frame's source path/name/rect/pivot/PPU, trim offset/size, atlas rect, and new pivot. `sourceUniqueTextureRgbaArea` sums the decoded RGBA dimensions of each distinct source texture referenced by that appearance; `sourceSpriteRectArea` is the sum of source Sprite rectangle pixels; `packedAtlasArea` is the sum of atlas RGBA pixel areas. The RGBA-area estimate excludes import/runtime overhead and compression/platform effects, and shared source textures may be counted once for each appearance that references them. It is an area comparison rather than a promised runtime-memory reduction.

## Persistence, rollback, and cleanup

Atlas PNGs are imported as separate texture assets. `Sprite.Create` makes the packed Sprite objects against those imported textures; `AssetDatabase.AddObjectToAsset` then persists the Sprite objects as subassets of the derived catalog. Generated subassets are marked with the `__ShowcaseLive_` name prefix. On a successful rebake, old prefixed Sprite subassets are removed only after new atlases, sprites, catalog references, and the receipt have been saved. Atlas files are content-addressed and retained, so an existing atlas remains available to an older catalog snapshot. On an exception before commit, the baker attempts to restore the existing catalog fields and receipt, removes newly attached prefixed sprites, and deletes only atlas PNGs created by that invocation. Unity asset import/save failures can still require manual inspection of the derived output folder; source assets remain untouched.

Unity Editor verification must confirm `Sprite.Create`-made Sprites remain valid as catalog subassets across save and domain reload. This helper is deliberately an Editor authoring operation, not a runtime path. Do not point gameplay at the result until that persistence check and the catalog reference scan pass.
