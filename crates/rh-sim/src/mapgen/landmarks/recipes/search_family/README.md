# Actual search recipes

This leaf ports the actual stage-4 Scorch (`fire`) and Gallows (`sentenced`) callbacks. Construct a recipe once with
`Recipe::from_definition`, then call immutable `apply` with the current runtime and admitted `RecipeInputs`.
No fixture supplies recipe rules or score answers. Template keys, rows, ordered jobs and all faction tuning are live
borrowed definition data and participate in allocation-free content visitation. The common count/scale, context streams,
noise, door selection, search tries/stride and runtime transaction limits remain owned by their accepted common modules.
Quarter tile radius units, doubled coordinates, eight orientations and the 1024 noise unit are source encodings.

Scorch keeps one lazy `open && simpleWallOk` byte memo across both margin retries and successful forges. Every margin
creates a fresh search session and copied planning overlay, while real placements retain the runtime's original hard
mask. Geometry and all scoring preserve source binary64 association; square roots use `rh_sim::math`. Successful forge
exclusion uses the source kth landmark feature, including any prior features. Gallows retains one search session across
both calls; territory crossing and strict separation are two independent FAR penalties, not exclusions. Its second call
runs even when the first refuses every candidate, and its door is read from the current ground after the first call.
Neither callback draws a main or independent context RNG word.

`tools/map-fixtures/landmark-recipes-search.ts` creates isolated TypeScript source copies with unique observational taps
and import rewrites. It invokes real `tryAttempt` for seeds 1, -1, 4294967297/attempt4294967296, 176, 54, 17/attempt1 and a
separately labelled styled seed-1 observer control. Before saving each case it requires complete final output equality
(including null) and actual source mapHash equality with the unmodified caller. No actual null result occurred in this
seven-case pool; no bounded scan or invented null-seed coverage is claimed. Linux x64 Node 22.23.4 is mandatory.
The source SHA inventory and exact case inventory are checked; missing/empty fixture data fails tests. `--check` requires
byte-for-byte fixture equality. There are also separately labelled synthetic calls to the actual source callbacks:
Gallows first-refusal/second-continuation with a shared reused cache, and Scorch with no camps.

The fixture retains lossless full stage input/output, ordered zone geometry/mask/edge fields and bit-pattern geometry,
original hard/territory/camps, planning overlay/memo snapshots, search identity/cache decisions, open/score/bound order
and f64 bits, fit requests, full transaction start/end states (including refusals), successful reservation order and
complete collision/terrain/ownership/features/wrote/reserved/scratch/counter states. Main stream initial value, prefix
words, state and continuations are captured; stream 3 and noise 103 seeds and zero-draw continuations are explicit.
Only the observer reconstructs a continuation; it never advances the live main generator stream.

Rust tests recompute the actual M3a prefix, execute the real Scorch/Gallows recipes, and compare every Scorch planning
open and overlay/memo plus every recipe score/bound argument and f64 bit. At every score/bound callback they compare
complete immutable runtime state, including scratch; complete zone exits and RNG continuations also match. One shared
state persists through all ordered zones. Other factions are explicitly source-placement replays solely to retain the
shared scratch prefix in this isolated leaf test. Parent integration must replace those with actual direct recipes and
recompute stage admission/protection. The coordinator-owned read-only test diagnostic accessor also compares every search cache/table decision, candidate
list, shortlist and ordered attempt/result with its complete post-attempt runtime state, including refused attempts.
Individual reservation events and fits are retained for parent/independent checks; the accepted template/runtime tests
verify those helpers separately.

Synthetic definition tests prove that tuning and actual template geometry/key/jobs affect live placement, and that every
live faction field and every template key/row/job changes visited content. Synthetic cases do not claim actual map-seed
coverage for every branch. Full generator orchestration, finished plain pins and certification remain outside this leaf.
